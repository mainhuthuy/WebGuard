# Task 1.5 — `InformationModule` (Rà soát lộ thông tin nhạy cảm)

> **Mục tiêu:** Xây dựng module kiểm tra các file và thông tin nhạy cảm bị lộ trên website.

---

## 📚 Lý thuyết: Information Disclosure là gì?

### Vấn đề

Nhiều website vô tình **để lộ** file cấu hình, source code, hoặc thông tin hệ thống mà ai cũng truy cập được. Hacker chỉ cần gõ URL:

```
https://example.com/.env          → Lộ mật khẩu database!
https://example.com/.git/HEAD     → Clone toàn bộ source code!
https://example.com/robots.txt    → Biết admin panel ở đâu!
```

Đây là lỗi **Information Disclosure** — thuộc nhóm *Security Misconfiguration* (OWASP Top 10:2021, mục A05).

---

## 📚 Các file nhạy cảm thường gặp

### 1. `/.env` — Severity: CRITICAL

File `.env` chứa **biến môi trường** — nơi developer lưu mật khẩu, API keys:

```env
DATABASE_URL=postgresql://admin:SuperSecret123@db.example.com/prod
JWT_SECRET=my-super-secret-key-never-share
AWS_ACCESS_KEY_ID=AKIA1234567890
```

→ Nếu lộ ra, hacker truy cập được database, cloud, mọi thứ!

**Nguyên nhân:** Developer quên chặn file `.env` trong cấu hình web server (Nginx/Apache).

---

### 2. `/.git/HEAD` — Severity: CRITICAL

Nếu file `/.git/HEAD` trả về `200 OK` → thư mục `.git` bị lộ → hacker có thể **clone toàn bộ source code**:

```bash
# Hacker dùng tool như git-dumper:
git-dumper https://example.com/.git/ ./source_code
# → Có toàn bộ code, commit history, secret keys trong code cũ!
```

**Nguyên nhân:** Deploy bằng `git pull` trên server mà không chặn thư mục `.git`.

---

### 3. `/robots.txt` — Severity: LOW

`robots.txt` hướng dẫn bot (Google, Bing) nên/không nên crawl gì:

```
User-agent: *
Disallow: /admin/
Disallow: /api/internal/
Disallow: /backup/
```

→ Hacker đọc `Disallow` = biết ngay **đường dẫn ẩn** mà admin muốn giấu!

**Lưu ý:** `robots.txt` tồn tại không phải lúc nào cũng xấu — nó là file chuẩn. Nhưng cần kiểm tra nội dung có lộ đường dẫn nhạy cảm không.

---

### 4. Server Header — Severity: MEDIUM

Response header `Server` tiết lộ **phần mềm và phiên bản** web server:

```
Server: Apache/2.4.41 (Ubuntu)
Server: nginx/1.18.0
```

→ Hacker biết version → tìm **CVE** (lỗ hổng đã công bố) → tấn công!

```
Apache 2.4.41 → CVE-2020-1927 (Open Redirect)
nginx 1.18.0  → CVE-2021-23017 (DNS Resolver)
```

---

### 5. X-Powered-By Header — Severity: MEDIUM

Header `X-Powered-By` tiết lộ **framework/ngôn ngữ**:

```
X-Powered-By: Express        → Node.js Express
X-Powered-By: PHP/7.4.3      → PHP version
X-Powered-By: ASP.NET        → .NET framework
```

→ Cùng nguyên lý: biết công nghệ → tìm lỗ hổng → tấn công!

---

### 6. `/wp-admin` — Severity: MEDIUM

Đường dẫn mặc định của **trang quản trị WordPress**:

```
https://example.com/wp-admin   → Trang đăng nhập admin!
https://example.com/wp-login.php
```

→ Nếu trả về `200 OK` → Hacker biết website dùng WordPress → tập trung tấn công:
- Brute-force mật khẩu admin
- Exploit plugin/theme lỗi thời
- Dùng WPScan quét toàn bộ lỗ hổng WordPress

**Lưu ý:** Check này chỉ có ý nghĩa với site WordPress. Với site khác sẽ trả về 404 → không có finding.

---

## 📚 Khác biệt kiến trúc với module trước

### HeadersModule: 1 request → nhiều checks

```
GET https://example.com → Response
  ├── Check header CSP?       → Thiếu → Finding
  ├── Check header HSTS?      → Thiếu → Finding
  └── Check header X-Frame?   → Có    → OK
```

### InformationModule: Nhiều requests → mỗi request 1 check

```
GET https://example.com/.env       → 404 → OK
GET https://example.com/.git/HEAD  → 404 → OK
GET https://example.com/robots.txt → 200 → Finding!
GET https://example.com            → Check Server header → Finding!
```

→ Module này gửi **nhiều HTTP requests** nên sẽ chậm hơn.

---

## 💻 Code hoàn chỉnh

File: `backend/app/modules/information.py`

```python
import httpx
from app.modules.base import HTTP_TIMEOUT, BaseModule

class InformationModule(BaseModule):
    @property
    def name(self) -> str:
        return "information"

    @property
    def description(self) -> str:
        return "Rà soát lộ file và thông tin nhạy cảm"

    SENSITIVE_PATHS = [
        {
            "path": "/.env",
            "severity": "critical",
            "description": "File .env chứa biến môi trường nhạy cảm",
            "remediation": "Chặn truy cập file .env trong web server"
        },
        {
            "path": "/.git/HEAD",
            "severity": "critical",
            "description": "Lộ thông tin về git repository",
            "remediation": "Chặn truy cập thư mục .git"
        },
        {
            "path": "/robots.txt",
            "severity": "low",
            "description": "File robots.txt có thể lộ đường dẫn ẩn",
            "remediation": "Kiểm tra robots.txt không chứa path nhạy cảm"
        },
        {
            "path": "/wp-admin",
            "severity": "medium",
            "description": "Cổng quản trị website",
            "remediation": "Tăng cường bảo mật cho cổng quản trị"
        }
    ]

    async def scan(self, url: str, **kwargs) -> list:
        findings = []
        async with httpx.AsyncClient(timeout=HTTP_TIMEOUT) as client:
            # Check từng sensitive path
            for item in self.SENSITIVE_PATHS:
                target = url.rstrip("/") + item["path"]
                try:
                    response = await client.get(target)
                    if response.status_code == 200:
                        findings.append({...})
                except httpx.HTTPError:
                    pass   # lỗi mạng/timeout của 1 path không ảnh hưởng path khác

            # Check Server + X-Powered-By headers
            try:
                response = await client.get(url)
                server = response.headers.get("Server")
                if server:
                    findings.append({...})

                xpb = response.headers.get("X-Powered-By")
                if xpb:
                    findings.append({...})
            except httpx.HTTPError:
                pass

        return findings
```

### Lưu ý thiết kế:

| Quyết định | Lý do |
|------------|-------|
| Path checks và Header checks tách riêng | Path cần nhiều requests, Header chỉ cần 1 |
| `X-Powered-By` không nằm trong `SENSITIVE_PATHS` | Vì nó là header, không phải đường dẫn file |
| Dùng `try/except httpx.HTTPError` bọc mỗi request | 1 path lỗi không ảnh hưởng các path khác |
| Bắt **`httpx.HTTPError`** thay vì `except:` trần | `except:` trần nuốt cả `KeyboardInterrupt`, `asyncio.CancelledError` (làm hỏng việc **hủy scan**) và mọi lỗi lập trình. Chỉ nên bắt đúng loại lỗi mình chủ đích bỏ qua |

## ⚠️ Giới hạn đã biết

| Vấn đề | Giải thích |
|---|---|
| Chỉ coi `200 OK` là "lộ" | `/wp-admin` thường trả **301/302** (chuyển tới trang đăng nhập). `httpx` mặc định **không theo redirect**, nên nhiều site WordPress thật sẽ *không* bị phát hiện |
| Soft-404 → dương tính giả | Một số site (SPA, trang lỗi tùy biến) trả `200` cho **mọi** đường dẫn, kể cả `/.env` → báo `critical` sai. Cách chặt hơn là kiểm tra nội dung (vd `/.git/HEAD` phải bắt đầu bằng `ref:`) |
| `/robots.txt` luôn bị báo `low` nếu tồn tại | Dù file chuẩn là hợp lệ; code **không** đọc nội dung `Disallow` như phần lý thuyết gợi ý |
| Không theo redirect là chủ ý | Theo redirect sẽ mở lối cho SSRF (site công khai chuyển hướng tới `http://127.0.0.1/...`) — nên mặc định tắt là an toàn |

---

## 🔑 Takeaway

1. **Information Disclosure** = lộ file cấu hình, source code, thông tin hệ thống
2. **`.env` và `.git`** = critical — lộ mật khẩu và source code
3. **Server/X-Powered-By headers** = lộ version → hacker tìm CVE
4. **Nhiều requests** = duyệt từng path, bọc try/except riêng
5. **Tách logic**: path checks vs header checks — không trộn lẫn
