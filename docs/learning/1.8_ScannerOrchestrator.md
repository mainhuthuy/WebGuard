# Task 1.8 — `Scanner` Orchestrator (Bộ điều phối quét song song)

> **Mục tiêu:** Kết nối tất cả 5 modules kiểm tra bảo mật và ScoringEngine thành một quy trình quét hoàn chỉnh, chạy bất đồng bộ song song (concurrent/async) với hiệu năng tối ưu.

---

## 📚 Lý thuyết: Tại sao cần Orchestrator và Chạy song song?

### 1. Vấn đề của chạy tuần tự (Sequential):
Nếu chạy tuần tự từng module:
```
HeadersModule (1.5s) ──► CookiesModule (0.5s) ──► SSLTLSModule (1.0s) ──► InformationModule (2.0s) ──► CORSModule (1.0s)
= TỔNG CỘNG: ~6.0 giây! ⏳ (Chờ đợi rất lâu)
```

### 2. Sức mạnh của chạy song song (`asyncio.gather`):
Cả 5 module đều thực hiện các tác vụ I/O mạng độc lập:
```
Scanner.scan(url)
  ├── HeadersModule     (1.5s) ─┐
  ├── CookiesModule     (0.5s)  │
  ├── SSLTLSModule      (1.0s)  ├─► asyncio.gather() ──► TỔNG CỘNG: ~2.0 giây! ⚡ (Nhanh gấp 3x - 5x)
  ├── InformationModule (2.0s)  │
  └── CORSModule        (1.0s) ─┘
```

---

## 📚 Kỹ thuật quan trọng trong Code

### 1. `asyncio.gather(*tasks, return_exceptions=True)`
- Dấu sao `*tasks` giúp unpack list các coroutine tasks.
- Tham số `return_exceptions=True` là **cực kỳ quan trọng trong thực tế**: nếu một module bị lỗi (ví dụ domain không hỗ trợ SSL port 443 làm SSLTLSModule crash), các module khác **vẫn tiếp tục chạy bình thường** và trả về kết quả thay vì làm crash toàn bộ scanner!

### 2. Gộp kết quả linh hoạt:
```python
findings = []
for result in results:
    if isinstance(result, list):
        findings.extend(result)
    elif isinstance(result, dict):
        findings.append(result)
```
Xử lý linh hoạt cả trường hợp module trả về `list` các finding hoặc chỉ 1 `dict`.

> ⚠️ Kết quả là `Exception` (module bị lỗi, do `return_exceptions=True`) rơi vào **không nhánh nào** của `if/elif` nên bị **bỏ qua âm thầm** — không log, không báo người dùng. Điều này giữ cho scanner không sập, nhưng cũng nghĩa là một module lỗi (vd. mục tiêu không phản hồi) chỉ cho ra "0 finding" chứ không báo lỗi.

## 💻 Cấu trúc `Scanner`

```python
import asyncio
from app.modules.headers import HeadersModule
from app.modules.cookies import CookiesModule
from app.modules.ssl_tls import SSLTLSModule
from app.modules.information import InformationModule
from app.modules.cors import CorsModule
from app.modules.scoring import ScoringEngine

class Scanner:
    def __init__(self, mode: str = "full"):
        # quick: chỉ Headers + SSL/TLS. full (mặc định): cả 5 module.
        if mode == "quick":
            self.modules = [HeadersModule(), SSLTLSModule()]
        else:
            self.modules = [
                HeadersModule(),
                CookiesModule(),
                SSLTLSModule(),
                InformationModule(),
                CorsModule(),
            ]
        self.scoring = ScoringEngine()

    async def scan(self, url: str) -> dict:
        tasks = [module.scan(url) for module in self.modules]
        results = await asyncio.gather(*tasks, return_exceptions=True)

        findings = []
        for result in results:
            if isinstance(result, list):
                findings.extend(result)
            elif isinstance(result, dict):
                findings.append(result)

        scoring = self.scoring.calculate(findings)

        return {
            "url": url,
            "total_findings": len(findings),
            "findings": findings,
            "scoring": scoring
        }
```

## 📚 Bổ sung ở Sprint 2–3: `scan_stream()` và chế độ `quick`

### Hai cách chạy, hai mục đích

| | `scan(url)` | `scan_stream(url, scan_id)` |
|---|---|---|
| Cách chạy | **Song song** (`asyncio.gather`) | **Tuần tự** từng module |
| Trả về | 1 dict kết quả cuối | `AsyncGenerator` — *yield* từng sự kiện |
| Dùng ở đâu | Quét nền (`ScanService.execute_scan`) | Luồng SSE (`GET /scan/{id}/stream`) — luồng mà giao diện dùng |
| Ưu điểm | Nhanh nhất | Báo tiến độ thật: biết module nào đang chạy / vừa xong |

Giao diện web đi theo đường `scan_stream`, nên trong thực tế các module chạy **nối đuôi nhau** (tổng thời gian ≈ tổng thời gian từng module), đổi lại thanh tiến trình phản ánh đúng thực tế.

### Tiến độ (`progress`) được tính thế nào?

```
start            →  5%
module_start(i)  →  10 + (i−1) × 75 / N        (i = 1..N)
module_completed →  10 + i × 75 / N
scoring          → 95%
complete         → 100%
```

Với 5 module (`full`): `module_start` = 10, 25, 40, 55, 70 và `module_completed` = 25, 40, 55, 70, 85. Với 2 module (`quick`): start = 10, 47; completed = 47, 85. Giá trị cuối cùng của `module_completed` luôn là **85**, không phải 90.

### Chế độ `quick` / `full`

`mode` được lưu trong DB (`scans.mode`) và truyền vào `Scanner(mode=...)`. `quick` bỏ Cookies, Information, CORS — nhanh hơn và ít request tới mục tiêu hơn, đổi lại ít kiểm tra hơn.
