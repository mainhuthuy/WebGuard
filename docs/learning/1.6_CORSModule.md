# Task 1.6 — `CORSModule` (Kiểm tra cấu hình sai CORS)

> **Mục tiêu:** Xây dựng module kiểm tra cấu hình CORS sai, phát hiện nguy cơ bị tấn công cross-origin.

---

## 📚 Lý thuyết: CORS là gì?

### Same-Origin Policy (SOP)

Trình duyệt có quy tắc bảo mật cơ bản: **trang web A không được gọi API của trang web B** (nếu khác origin).

**Origin** = `protocol + domain + port`:
```
https://myapp.com:443    ← Đây là 1 origin
https://api.bank.com:443 ← Đây là origin KHÁC
http://myapp.com:80      ← Khác origin (khác protocol)
https://myapp.com:8080   ← Khác origin (khác port)
```

### CORS = "ngoại lệ" cho SOP

CORS cho phép server **nới lỏng** SOP — nói với trình duyệt "trang web này ĐƯỢC PHÉP gọi API của tôi":

```
Trình duyệt: "myapp.com muốn gọi API của bank.com, có được không?"
Bank.com: "Access-Control-Allow-Origin: https://myapp.com" ← Cho phép!
Trình duyệt: "OK, cho qua!"
```

### Vấn đề: Cấu hình CORS quá lỏng

```
✅ Access-Control-Allow-Origin: https://myapp.com     ← Chỉ myapp.com
❌ Access-Control-Allow-Origin: *                      ← AI CŨNG ĐƯỢC
❌ Phản hồi lại origin từ request                      ← Tin mọi người
```

## 📚 3 Lỗi CORS cần kiểm tra

### 1. Wildcard Origin (`*`) — Severity: HIGH

```
Access-Control-Allow-Origin: *
```

**Nghĩa là:** Bất kỳ website nào trên internet đều có thể gọi API này.

**Tấn công:**
```javascript
// Trên trang evil.com:
fetch("https://victim-api.com/user/profile")
  .then(r => r.json())
  .then(data => {
    // Đọc được dữ liệu người dùng!
    sendToHacker(data);
  });
```

> 💡 Wildcard `*` không cho phép gửi cookie (trình duyệt chặn). Nên severity là HIGH chứ không phải CRITICAL.

---

### 2. Origin Reflection — Severity: CRITICAL

Server **phản hồi lại bất kỳ Origin nào** trong request:

```
Request:  Origin: https://evil.com
Response: Access-Control-Allow-Origin: https://evil.com  ← Phản hồi lại!
```

**Nguy hiểm hơn wildcard** vì:
- Có thể kết hợp với `Credentials: true` → đánh cắp cookie
- Server "tin" mọi origin thay vì kiểm tra whitelist

**Cách test:** Gửi request với header `Origin: https://evil.com` giả mạo, xem server có echo lại không.

---

### 3. Credentials + Lax Origin — Severity: CRITICAL

```
Access-Control-Allow-Origin: https://evil.com   ← Phản hồi origin
Access-Control-Allow-Credentials: true           ← Cho phép gửi cookie!
```

**Tổ hợp chết chóc!** Trang evil.com có thể:
1. Gọi API bank.com
2. Trình duyệt **tự động gửi kèm cookie** bank.com
3. Bank.com xử lý request như người dùng hợp lệ
4. Evil.com đọc được response → **đánh cắp dữ liệu**

```javascript
// Trên evil.com — đánh cắp thông tin ngân hàng:
fetch("https://bank.com/api/account/balance", {
  credentials: "include"  // Gửi kèm cookie!
})
.then(r => r.json())
.then(data => sendToHacker(data));
```

## 📚 Kỹ thuật: Gửi request với header giả mạo

### Khác biệt với module trước

Các module trước gửi request **bình thường** rồi phân tích response. Module CORS cần **giả mạo header** để test phản ứng server:

```python
# Request bình thường
response = await client.get(url)

# Request với Origin giả mạo — test xem server có "tin" không
response = await client.get(url, headers={"Origin": "https://evil.com"})
```

### Tái sử dụng response

Check 3 (Credentials) dùng lại response từ Check 2 — không cần gửi request lần 3:

```python
# Check 2: Origin reflection
response = await client.get(url, headers={"Origin": "https://evil.com"})
acao = response.headers.get("access-control-allow-origin")

# Check 3: Credentials — dùng lại response trên
acac = response.headers.get("access-control-allow-credentials")
if acac and acac.lower() == "true" and acao and acao != "*":
    # CRITICAL!
```

## 💻 Code hoàn chỉnh

File: `backend/app/modules/cors.py`

```python
import httpx
from app.modules.base import HTTP_TIMEOUT, BaseModule

class CorsModule(BaseModule):
    @property
    def name(self) -> str:
        return "CORS"

    @property
    def description(self) -> str:
        return "Kiểm tra cấu hình sai CORS"

    async def scan(self, url: str, **kwargs) -> list:
        findings = []
        async with httpx.AsyncClient(timeout=HTTP_TIMEOUT) as client:
            # Check 1: Wildcard *
            response = await client.get(url)
            acao = response.headers.get("access-control-allow-origin")
            if acao == "*":
                findings.append({
                    "module": self.name,
                    "name": "cors_wildcard",
                    "severity": "high",
                    "description": "Server cho phép mọi origin truy cập",
                    "remediation": "Chỉ định cụ thể domain được phép",
                    "url": url
                })

            # Check 2: Origin reflection
            response = await client.get(url, headers={"Origin": "https://evil.com"})
            acao = response.headers.get("access-control-allow-origin")
            if acao == "https://evil.com":
                findings.append({
                    "module": self.name,
                    "name": "cors_origin_reflection",
                    "severity": "critical",
                    "description": "Server phản hồi lại bất kỳ Origin nào",
                    "remediation": "Kiểm tra Origin trong whitelist",
                    "url": url
                })

            # Check 3: Credentials (dùng lại response check 2)
            acac = response.headers.get("access-control-allow-credentials")
            if acac and acac.lower() == "true" and acao and acao != "*":
                findings.append({
                    "module": self.name,
                    "name": "cors_credentials_exposed",
                    "severity": "critical",
                    "description": "Server cho phép gửi cookie cross-origin",
                    "remediation": "Tắt Allow-Credentials hoặc giới hạn origin",
                    "url": url
                })

        return findings
```

## ⚠️ Lưu ý khi đối chiếu với code

1. **Tên module viết hoa:** `name` trả về `"CORS"` trong khi các module khác viết thường (`headers`, `cookies`, `ssl_tls`, `information`). Giá trị này đi thẳng vào trường `module` của finding và sự kiện SSE; frontend phải chuẩn hóa về chữ thường (`toModuleName` trong `services/mappers.ts`).
2. **Check 3 chưa chặt như lý thuyết:** điều kiện trong code là `acac == "true" and acao and acao != "*"` — nó chỉ cần `acao` **khác `*`**, chứ không đòi `acao == "https://evil.com"` (tức server thật sự *phản xạ* origin lạ). Hệ quả: một server cấu hình đúng — `Access-Control-Allow-Origin: https://myapp.com` kèm `Allow-Credentials: true` — vẫn bị báo `critical`, là một **dương tính giả**. Điều kiện đúng với mô tả lý thuyết phải là `acao == "https://evil.com"` (hoặc nói chung: `acao` bằng đúng Origin ta gửi). Đây là điểm có thể cải thiện sau.
3. Một lượt quét gửi **2 request** (check 1 không có `Origin`, check 2–3 dùng `Origin: https://evil.com`), không phải 3.

## 🔑 Takeaway

1. **CORS** = cơ chế cho phép/chặn cross-origin requests
2. **Wildcard `*`** = ai cũng gọi được API (nhưng không gửi cookie)
3. **Origin Reflection** = server tin mọi origin → nguy hiểm hơn wildcard
4. **Credentials + lax origin** = đánh cắp cookie cross-site → CRITICAL
5. **Test bằng header giả mạo** — gửi `Origin: evil.com` xem server phản ứng thế nào
6. **Tái sử dụng response** — không gửi request thừa khi có thể dùng lại
