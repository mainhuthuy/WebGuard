## 📚 Lý thuyết: CORS là gì?

### Same-Origin Policy (SOP)

Trình duyệt có quy tắc bảo mật cơ bản: **trang web A không được gọi API của trang web B** (nếu khác origin).

**Origin** = `protocol + domain + port`:
```
https://myapp.com:443    ← Đây là 1 origin
https://api.bank.com:443 ← Đây là origin KHÁC
http://myapp.com:80      ← Khác origin (khác protocol)
https://myapp.com:8080   ← Khác origin (khác port)
```

### CORS = "ngoại lệ" cho SOP

CORS cho phép server **nới lỏng** SOP — nói với trình duyệt "trang web này ĐƯỢC PHÉP gọi API của tôi":

```
Trình duyệt: "myapp.com muốn gọi API của bank.com, có được không?"
Bank.com: "Access-Control-Allow-Origin: https://myapp.com" ← Cho phép!
Trình duyệt: "OK, cho qua!"
```

### Vấn đề: Cấu hình CORS quá lỏng

```
✅ Access-Control-Allow-Origin: https://myapp.com     ← Chỉ myapp.com
❌ Access-Control-Allow-Origin: *                      ← AI CŨNG ĐƯỢC
❌ Phản hồi lại origin từ request                      ← Tin mọi người
```

## 📚 3 Lỗi CORS cần kiểm tra

### 1. Wildcard Origin (`*`) — Severity: HIGH

```
Access-Control-Allow-Origin: *
```

**Nghĩa là:** Bất kỳ website nào trên internet đều có thể gọi API này.

**Tấn công:**
```javascript
// Trên trang evil.com:
fetch("https://victim-api.com/user/profile")
  .then(r => r.json())
  .then(data => {
    // Đọc được dữ liệu người dùng!
    sendToHacker(data);
  });
```

> 💡 Wildcard `*` không cho phép gửi cookie (trình duyệt chặn). Nên severity là HIGH chứ không phải CRITICAL.

---

### 2. Origin Reflection — Severity: CRITICAL

Server **phản hồi lại bất kỳ Origin nào** trong request:

```
Request:  Origin: https://evil.com
Response: Access-Control-Allow-Origin: https://evil.com  ← Phản hồi lại!
```

**Nguy hiểm hơn wildcard** vì:
- Có thể kết hợp với `Credentials: true` → đánh cắp cookie
- Server "tin" mọi origin thay vì kiểm tra whitelist

**Cách test:** Gửi request với header `Origin: https://evil.com` giả mạo, xem server có echo lại không.

---

### 3. Credentials + Lax Origin — Severity: CRITICAL

```
Access-Control-Allow-Origin: https://evil.com   ← Phản hồi origin
Access-Control-Allow-Credentials: true           ← Cho phép gửi cookie!
```

**Tổ hợp chết chóc!** Trang evil.com có thể:
1. Gọi API bank.com
2. Trình duyệt **tự động gửi kèm cookie** bank.com
3. Bank.com xử lý request như người dùng hợp lệ
4. Evil.com đọc được response → **đánh cắp dữ liệu**

```javascript
// Trên evil.com — đánh cắp thông tin ngân hàng:
fetch("https://bank.com/api/account/balance", {
  credentials: "include"  // Gửi kèm cookie!
})
.then(r => r.json())
.then(data => sendToHacker(data));
```

## 📚 Kỹ thuật: Gửi request với header giả mạo

### Khác biệt với module trước

Các module trước gửi request **bình thường** rồi phân tích response. Module CORS cần **giả mạo header** để test phản ứng server:

```python
# Request bình thường
response = await client.get(url)

# Request với Origin giả mạo — test xem server có "tin" không
response = await client.get(url, headers={"Origin": "https://evil.com"})
```

### Tái sử dụng response

Check 3 (Credentials) dùng lại response từ Check 2 — không cần gửi request lần 3:

```python
# Check 2: Origin reflection
response = await client.get(url, headers={"Origin": "https://evil.com"})
acao = response.headers.get("access-control-allow-origin")

# Check 3: Credentials — dùng lại response trên, và chỉ nguy hiểm khi origin lạ được PHẢN XẠ
acac = response.headers.get("access-control-allow-credentials")
if acao == "https://evil.com" and acac and acac.lower() == "true":
    # CRITICAL!
```

## 💻 Code hoàn chỉnh

File: `backend/app/modules/cors.py`

```python
import httpx
from app.modules.base import HTTP_TIMEOUT, BaseModule

class CorsModule(BaseModule):
    @property
    def name(self) -> str:
        return "CORS"

    @property
    def description(self) -> str:
        return "Kiểm tra cấu hình sai CORS"

    async def scan(self, url: str, **kwargs) -> list:
        findings = []
        async with httpx.AsyncClient(timeout=HTTP_TIMEOUT) as client:
            # Check 1: Wildcard *
            response = await client.get(url)
            acao = response.headers.get("access-control-allow-origin")
            if acao == "*":
                findings.append({
                    "module": self.name,
                    "name": "cors_wildcard",
                    "severity": "high",
                    "description": "Server cho phép mọi origin truy cập",
                    "remediation": "Chỉ định cụ thể domain được phép",
                    "url": url
                })

            # Check 2: Origin reflection
            response = await client.get(url, headers={"Origin": EVIL_ORIGIN})
            acao = response.headers.get("access-control-allow-origin")
            reflected = acao == EVIL_ORIGIN
            if reflected:
                findings.append({
                    "module": self.name,
                    "name": "cors_origin_reflection",
                    "severity": "critical",
                    "description": "Server phản hồi lại bất kỳ Origin nào",
                    "remediation": "Kiểm tra Origin trong whitelist",
                    "url": url
                })

            # Check 3: Credentials (dùng lại response check 2) — chỉ khi origin lạ được phản xạ lại.
            # Allow-Origin cố định + Allow-Credentials: true là cấu hình HỢP LỆ.
            acac = response.headers.get("access-control-allow-credentials")
            if reflected and acac and acac.lower() == "true":
                findings.append({
                    "module": self.name,
                    "name": "cors_credentials_exposed",
                    "severity": "critical",
                    "description": "Server cho phép gửi cookie cross-origin",
                    "remediation": "Tắt Allow-Credentials hoặc giới hạn origin",
                    "url": url
                })

        return findings
```

## ⚠️ Lưu ý khi đối chiếu với code

1. **Tên module viết hoa:** `name` trả về `"CORS"` trong khi các module khác viết thường (`headers`, `cookies`, `ssl_tls`, `information`). Giá trị này đi thẳng vào trường `module` của finding và sự kiện SSE; frontend phải chuẩn hóa về chữ thường (`toModuleName` trong `services/mappers.ts`).
2. **Check 3 chỉ tính khi origin lạ được *phản xạ* (đã sửa):** ban đầu điều kiện là `acac == "true" and acao and acao != "*"` — chỉ cần `acao` khác `*`. Hệ quả: server cấu hình **đúng** (`Access-Control-Allow-Origin: https://myapp.com` + `Allow-Credentials: true`) vẫn bị báo `critical` — một **dương tính giả**. Điều kiện hiện tại là `reflected and acac == "true"`, với `reflected = (acao == "https://evil.com")`. Bảng quyết định:

   | `Allow-Origin` (khi gửi `Origin: https://evil.com`) | `Allow-Credentials` | Kết quả |
   |---|---|---|
   | `https://myapp.com` (cố định) | `true` | **Không có finding** (cấu hình hợp lệ) |
   | `https://evil.com` (phản xạ) | không có | `cors_origin_reflection` |
   | `https://evil.com` (phản xạ) | `true` | `cors_origin_reflection` + `cors_credentials_exposed` |
   | `*` | `true` | `cors_wildcard` (trình duyệt từ chối `*` kèm cookie nên không tính rò cookie) |

   Test: `tests/unit/test_cors_credentials.py`. Bài học: *một điều kiện lỏng ("khác `*`") thay cho điều kiện đúng ("bằng đúng origin ta gửi")* sinh dương tính giả — và dương tính giả làm giảm niềm tin vào công cụ.
3. Một lượt quét gửi **2 request** (check 1 không có `Origin`, check 2–3 dùng `Origin: https://evil.com`), không phải 3.

## 📚 Cập nhật sau Sprint 1 — origin `null` và whitelist so khớp một phần

### 1. Origin `null` — giá trị đặc biệt mà trình duyệt tự gửi

`Origin: null` không phải origin "không có" — nó là giá trị **trình duyệt tự gửi thay cho kẻ tấn công** trong một số tình huống hợp lệ về mặt kỹ thuật:
- Trang mở từ file cục bộ (`file://...`)
- `<iframe sandbox>` **không** có thuộc tính `allow-same-origin`
- Trang chuyển hướng qua một số kiểu redirect nhất định

→ Nếu whitelist của server có `"null"` trong danh sách origin được tin (thường do dev thêm để test cục bộ rồi quên xoá), **bất kỳ ai** cũng tạo được request mang `Origin: null` bằng một iframe sandbox đơn giản — không cần kiểm soát domain nào cả:
```python
response = await client.get(url, headers={"Origin": "null"})
if response.headers.get("access-control-allow-origin") == "null":
    findings.append({"name": "cors_null_origin", "severity": "high", ...})
```

### 2. Whitelist so khớp "một phần" — lỗi code thường gặp

Một whitelist CORS triển khai sai phổ biến nhất là dùng `startswith`/`endswith`/regex lỏng thay vì so khớp **chính xác toàn bộ origin**:
```python
# Code server VÍ DỤ (sai) — tưởng là chỉ cho phép example.com:
if origin.startswith("https://example.com"):
    allow_origin = origin
```
Lỗi này cho phép `https://example.com.evil.com` (evil.com là domain thật, `example.com` chỉ là **subdomain con** của nó — trình duyệt coi đây là origin hợp lệ, khác hẳn `https://example.com`) lọt qua `startswith`. Tương tự `endswith("example.com")` cho qua `https://evilexample.com`.

Module giả lập đúng 2 kiểu tấn công đó:
```python
host = urlparse(url).hostname   # "example.com"
for forged in (f"https://{host}.evil.com", f"https://evil{host}"):
    response = await client.get(url, headers={"Origin": forged})
    if response.headers.get("access-control-allow-origin") == forged:
        findings.append({"name": "cors_weak_origin_validation", "severity": "high", ...})
        break   # 1 bằng chứng là đủ, không cần thử tiếp
```
Check này **chỉ chạy khi site chưa bị báo `cors_origin_reflection`** (`if host and not reflected`) — vì nếu server đã phản xạ *mọi* origin thì lỗi "so khớp lỏng" không còn ý nghĩa, đã có finding nghiêm trọng hơn bao trùm rồi (tránh báo trùng 2 lỗi cho cùng 1 nguyên nhân).

### 3. Kết quả kiểm chứng (test mới)

`tests/unit/test_cors_origins.py` giả lập "whitelist" của server bằng một hàm `trusted(origin) -> bool` tùy biến mỗi test — ví dụ mô phỏng đúng lỗi `startswith`:
```python
async def test_suffix_attack_origin_is_reported() -> None:
    assert await _scan(lambda o: o.startswith("https://example.com")) == ["cors_weak_origin_validation"]
```

### 🔑 Takeaway (bổ sung)

1. **`Origin: null` là giá trị hợp lệ do trình duyệt sinh ra trong một số ngữ cảnh** — đưa nó vào whitelist tưởng "chỉ để test" lại mở cửa cho mọi iframe sandbox.
2. **So khớp whitelist phải là so khớp *chính xác*, không phải "chứa chuỗi con"** — `startswith`/`endswith` trên domain luôn có cách lách bằng domain con hoặc domain nối chuỗi.
3. **Khi nhiều check cùng phát hiện một nguyên nhân gốc, chỉ nên báo check nghiêm trọng nhất** — tránh làm loãng danh sách lỗi bằng các finding trùng ý nghĩa.
