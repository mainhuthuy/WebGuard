## 📚 Lý thuyết: SSL/TLS là gì?

### Mã hóa kết nối

SSL (Secure Sockets Layer) và TLS (Transport Layer Security) là giao thức **mã hóa** dữ liệu giữa trình duyệt và server.

```
Không có SSL (HTTP):
  Trình duyệt → "password: 123456" → [Hacker đọc được!] → Server

Có SSL (HTTPS):
  Trình duyệt → "a8#kL9$xZ..." → [Hacker: ???] → Server giải mã
```

### Chứng chỉ SSL là gì?

Chứng chỉ SSL giống như **CMND của website** — chứng minh website là thật, không phải giả mạo.

- **Ai cấp?** CA (Certificate Authority) — ví dụ: Let's Encrypt, DigiCert, Comodo
- **Chứa gì?** Tên miền, ngày hết hạn, thuật toán mã hóa, khóa công khai
- **Icon 🔒** trên trình duyệt = chứng chỉ hợp lệ

## 📚 Khác biệt với module trước

| | Headers/Cookies Module | SSLTLSModule |
|--|----------------------|--------------|
| **Thư viện** | `httpx` (HTTP client) | `ssl` + `socket` (built-in) |
| **Kết nối** | HTTP request → response | TCP socket → SSL handshake |
| **Dữ liệu** | Response headers/cookies | Chứng chỉ X.509 |

### Tại sao không dùng httpx?

`httpx` cho em response HTTP (headers, body, cookies), nhưng **không cho** thông tin chi tiết về SSL:
- Phiên bản TLS đang dùng
- Ngày hết hạn chứng chỉ
- Thuật toán mã hóa

→ Phải dùng `ssl` + `socket` để truy cập trực tiếp tầng SSL/TLS.

## 📚 Cách Python kết nối SSL

### Bước 1: Tạo SSL Context

```python
import ssl
context = ssl.create_default_context()
```

`create_default_context()` tạo context với cấu hình an toàn mặc định:
- Chỉ chấp nhận **TLS 1.2 trở lên** (Python ≥ 3.10 đặt `minimum_version = TLSv1_2`)
- Kiểm tra chứng chỉ có hợp lệ (chuỗi CA tin cậy, chưa hết hạn)
- Kiểm tra hostname khớp

> ⚠️ **Hệ quả quan trọng cho module này:** vì *client* (scanner) từ chối TLS < 1.2 ngay lúc bắt tay, một server **chỉ** hỗ trợ TLS 1.0/1.1 làm `wrap_socket()` ném `ssl.SSLError`. Nếu chỉ dựa vào kết nối mặc định, ta chỉ thấy "không kết nối được" (`ssl_connection_failed`) chứ không biết nguyên nhân là TLS lỗi thời — và cũng **không bao giờ thấy** một server *hỗ trợ cả TLS 1.3 lẫn TLS 1.0* (kết nối mặc định sẽ thỏa thuận 1.3).
>
> **Cách xử lý (hàm `_probe_legacy_tls`):** sau (hoặc khi thất bại) kết nối mặc định, scanner **thử bắt tay riêng từng phiên bản cũ**, ép `minimum_version = maximum_version = TLSv1` rồi `TLSv1_1` (và `set_ciphers("ALL:@SECLEVEL=0")` để OpenSSL chịu dùng bộ mã hóa cũ), **không xác minh chứng chỉ** vì chỉ cần biết server *có chấp nhận* giao thức đó không. Kết quả:
>
> | Tình huống | Finding |
> |---|---|
> | Server hỗ trợ TLS 1.3 **và** còn nhận TLS 1.0/1.1 | `outdated_tls_version` (high): "vẫn chấp nhận TLSv1, TLSv1.1" |
> | Server **chỉ** có TLS cũ (bắt tay mặc định thất bại, dò thấy TLS cũ) | `outdated_tls_version` (high): "chỉ hỗ trợ TLSv1" — *không* báo thêm `ssl_connection_failed` |
> | Chứng chỉ sai/tự ký (`SSLCertVerificationError`) hoặc lỗi mạng thuần (`ConnectionRefusedError`) | `ssl_connection_failed`; **không** dò TLS cũ vì nguyên nhân không phải phiên bản |
> | Máy quét không thể thử TLS 1.0 (OpenSSL tắt hẳn) | Bỏ qua phiên bản đó — "không biết", **không** có nghĩa là an toàn |
>
> Mỗi lần quét tốn thêm tối đa 2 kết nối ngắn (timeout 5s mỗi lần), chạy trong thread để không chặn event loop.
>
> ⚠️ **Lưu ý khi tự thử trong môi trường có proxy chặn giữa (corporate/sandbox):** proxy tự kết thúc TLS nên *mọi* server đều có vẻ "chấp nhận TLS 1.0", kể cả `google.com`. Kết quả dò chỉ đáng tin khi đường mạng tới server là trực tiếp. Vì lý do đó test của project dựng **server TLS cục bộ có khóa phiên bản** thay vì gọi site thật.

### Bước 2: Kết nối TCP Socket

```python
import socket
with socket.create_connection(("google.com", 443)) as sock:
    ...
```

Socket = kết nối mạng ở tầng thấp (TCP). Port 443 = HTTPS.

### Bước 3: Bọc SSL lên Socket

```python
with context.wrap_socket(sock, server_hostname="google.com") as ssock:
    cert = ssock.getpeercert()      # Thông tin chứng chỉ
    tls_version = ssock.version()    # "TLSv1.3"
```

`wrap_socket()` thực hiện **SSL handshake** — quá trình 2 bên thỏa thuận mã hóa:

```
Client: "Tôi hỗ trợ TLS 1.2, TLS 1.3"
Server: "OK, dùng TLS 1.3, đây là chứng chỉ của tôi"
Client: "Chứng chỉ hợp lệ, bắt đầu mã hóa!"
→ Kết nối an toàn được thiết lập
```

## 📚 Xử lý ngày hết hạn chứng chỉ

### Lấy ngày hết hạn:

```python
cert = ssock.getpeercert()
cert['notAfter']  # "Sep 30 00:00:00 2025 GMT"
```

### Parse timestamp an toàn:

```python

elif days_left < 30:    # Sắp hết hạn → medium
```

## 📚 Vì sao dùng `asyncio.to_thread`? (socket đồng bộ trong hàm `async`)

`socket.create_connection` và `wrap_socket` là **hàm đồng bộ (blocking)**: trong lúc chờ kết nối/bắt tay, chúng giữ nguyên luồng đang chạy. Nếu gọi thẳng trong `async def scan`, **cả event loop bị đứng** — mọi request khác của server (kể cả các luồng SSE đang chạy) phải chờ.

Giải pháp: đưa phần blocking vào một hàm thường rồi chạy trong luồng phụ:

```python
def _fetch_certificate(host: str, port: int) -> tuple[dict, str | None]:
    context = ssl.create_default_context()
    with socket.create_connection((host, port), timeout=HTTP_TIMEOUT) as sock:
        with context.wrap_socket(sock, server_hostname=host) as ssock:
            return ssock.getpeercert() or {}, ssock.version()

cert, tls_version = await asyncio.to_thread(_fetch_certificate, host, port)
```

- `await asyncio.to_thread(...)` = "chạy hàm này ở thread khác, trong lúc đó event loop vẫn phục vụ việc khác".
- `timeout=HTTP_TIMEOUT` tránh treo vô hạn khi firewall âm thầm bỏ gói tin.
- Tách `_fetch_certificate` thành hàm riêng còn giúp **test dễ**: test chỉ cần thay hàm này bằng bản giả trả về chứng chỉ mong muốn, không cần mạng thật (xem `tests/unit/test_ssl_tls.py`).
- Cổng lấy từ URL (`parsed.port or 443`), nên `https://example.com:8443` được kiểm tra đúng cổng.

## 📚 Xử lý lỗi kết nối (Exception Handling)

SSL có thể lỗi vì nhiều lý do:
- Website không hỗ trợ HTTPS
- Chứng chỉ tự ký (self-signed)
- Firewall chặn port 443

→ Bọc trong `try/except` và trả finding thay vì crash:

```python
try:
    # Kết nối SSL...
except Exception as e:
    findings.append({
        "name": "ssl_connection_failed",
        "severity": "critical",
        "description": f"Không thể kết nối: {str(e)}"
    })
    return findings  # Return sớm, không check tiếp
```

## 💻 Code hoàn chỉnh

File: `backend/app/modules/ssl_tls.py`

```python
import asyncio
import ssl
import socket
import datetime
from urllib.parse import urlparse
from app.modules.base import HTTP_TIMEOUT, BaseModule

def _fetch_certificate(host: str, port: int) -> tuple[dict, str | None]:
    """Kết nối TLS (blocking) và trả về (cert, phiên bản TLS). Chạy trong thread riêng."""
    context = ssl.create_default_context()
    with socket.create_connection((host, port), timeout=HTTP_TIMEOUT) as sock:
        with context.wrap_socket(sock, server_hostname=host) as ssock:
            return ssock.getpeercert() or {}, ssock.version()

class SSLTLSModule(BaseModule):
    @property
    def name(self) -> str:
        return "ssl_tls"

    @property
    def description(self) -> str:
        return "Kiểm tra cấu hình SSL/TLS của trang web"

    async def scan(self, url: str, **kwargs) -> list:
        parsed = urlparse(url)
        host = parsed.hostname or ""
        port = parsed.port or 443
        findings = []

        # Bước 1: Kết nối SSL (blocking -> chạy trong thread)
        try:
            cert, tls_version = await asyncio.to_thread(_fetch_certificate, host, port)
        except Exception as e:
            # Lỗi SSL không phải do chứng chỉ -> thử xem có phải server chỉ có TLS cũ
            if isinstance(e, ssl.SSLError) and not isinstance(e, ssl.SSLCertVerificationError):
                legacy = await asyncio.to_thread(_probe_legacy_tls, host, port)
                if legacy:
                    return [self._legacy_finding(legacy, url, only_legacy=True)]
            findings.append({...})  # SSL connection failed
            return findings

        # Bước 2: Check TLS cũ — phiên bản vừa thỏa thuận VÀ các phiên bản cũ server còn chấp nhận
        legacy = await asyncio.to_thread(_probe_legacy_tls, host, port)
        if tls_version in ["TLSv1", "TLSv1.1", "SSLv3"] and tls_version not in legacy:
            legacy.append(tls_version)
        if legacy:
            findings.append(self._legacy_finding(legacy, url))  # Outdated TLS

        # Bước 3: Check chứng chỉ hết hạn
        if not cert:
            return findings
        expire_timestamp = ssl.cert_time_to_seconds(cert['notAfter'])
        expire_date = datetime.datetime.fromtimestamp(expire_timestamp, tz=datetime.timezone.utc)
        days_left = (expire_date - datetime.datetime.now(datetime.timezone.utc)).days

        if days_left < 0:
            findings.append({...})   # Đã hết hạn → critical
        elif days_left < 30:
            findings.append({...})   # Sắp hết hạn → medium

        return findings
```

## 🔑 Takeaway

1. **SSL/TLS** = mã hóa kết nối, chứng chỉ = CMND của website
2. **TLS 1.0/1.1** đã deprecated — chỉ dùng TLS 1.2 hoặc 1.3
3. **`ssl` + `socket`** thay vì `httpx` — để truy cập thông tin chứng chỉ chi tiết
4. **`urlparse()`** — cách an toàn để parse URL thay vì `replace()`
5. **`ssl.cert_time_to_seconds()`** — parse ngày chứng chỉ tự động
6. **`try/except` + return sớm** — xử lý lỗi kết nối gracefully
7. **`__pycache__`** — xóa khi code thay đổi mà kết quả không đổi
8. **`asyncio.to_thread`** — luôn đưa code blocking (socket, file, CPU nặng) ra khỏi event loop
9. **Muốn biết server còn hỗ trợ gì, phải thử từng thứ** — kết nối mặc định chỉ cho biết phiên bản *được chọn*, không cho biết các phiên bản server *còn chấp nhận*; vì vậy cần dò riêng từng phiên bản cũ
10. **Kiểm thử bằng server giả cục bộ** thay vì site thật — ổn định, không phụ thuộc mạng (và không bị proxy làm sai lệch)

## 📚 Cập nhật sau Sprint 1 — phân loại lỗi chứng chỉ, bộ mã hóa yếu, và TLS 1.3

### 1. Sửa lỗi: `cert_expired` không bao giờ chạm được

Bug đã tự ghi lại ở mục kết quả kiểm chứng: `ssl.create_default_context()` **xác minh chứng chỉ ngay trong lúc bắt tay** — nếu chứng chỉ hết hạn/tự ký/sai hostname, `wrap_socket()` ném `SSLCertVerificationError` **trước khi** code kịp gọi `getpeercert()` để tự tính `days_left`. Code cũ bắt mọi lỗi (trừ lỗi liên quan TLS cũ) thành một finding chung `ssl_connection_failed` — đúng về bản chất ("không kết nối được") nhưng **mất hết thông tin hữu ích**: người dùng không biết lỗi vì hết hạn, tự ký, hay sai tên miền.

### 2. Lý thuyết: đọc "lý do từ chối" từ `SSLCertVerificationError`

`ssl.SSLCertVerificationError` (lớp con của `SSLError`) mang theo 2 thuộc tính OpenSSL gắn kèm:
```python
error.verify_code     # số nguyên, mã lỗi X.509 chuẩn OpenSSL (vd 10 = hết hạn, 18 = tự ký)
error.verify_message   # chuỗi mô tả do OpenSSL sinh ra
```
Mã số ổn định hơn chuỗi message (message có thể đổi theo phiên bản OpenSSL), nhưng project dùng **cả hai** — ưu tiên mã số, soi thêm chuỗi để bắt các trường hợp mã số không có mặt (vd bản Python cũ):
```python
def _classify_cert_error(error: ssl.SSLCertVerificationError) -> str | None:
    code = getattr(error, "verify_code", None)
    text = str(getattr(error, "verify_message", None) or error).lower()
    if code == 10 or "expired" in text:
        return "cert_expired"
    if code == 62 or "hostname" in text or "doesn't match" in text:
        return "cert_hostname_mismatch"
    if code in (18, 19) or "self-signed" in text:
        return "cert_self_signed"
    if code in (20, 21) or "local issuer" in text or "verify the first certificate" in text:
        return "cert_untrusted_chain"
    return None
```
→ 4 finding mới, tất cả `critical` (giữ nguyên mức độ của `ssl_connection_failed` cũ — vẫn là "không thể tin kết nối"), nhưng **mô tả đúng nguyên nhân** và **đề xuất khắc phục khác nhau** (gia hạn chứng chỉ ≠ cấp đúng tên miền ≠ dùng CA tin cậy ≠ gửi kèm chứng chỉ trung gian). Lỗi không nhận diện được (`code` lạ) vẫn rơi về `ssl_connection_failed` như cũ — **không đoán bừa**.

### 3. Dò bộ mã hóa yếu (RC4, 3DES, NULL/anonymous)

Tương tự cách dò TLS cũ ở `_probe_legacy_tls` (mục trên), nhưng lần này cố định **phiên bản** TLS ở mức ≤ 1.2 (TLS 1.3 không cho chọn cipher theo kiểu cũ — bộ cipher của nó luôn an toàn) và đổi **bộ cipher** muốn thử:
```python
WEAK_CIPHER_GROUPS = (("RC4", "RC4"), ("3DES", "3DES"), ("NULL/anonymous", "aNULL:eNULL"))

def _probe_weak_ciphers(host: str, port: int) -> list[str]:
    accepted = []
    for label, cipher_string in WEAK_CIPHER_GROUPS:
        context = ssl.SSLContext(ssl.PROTOCOL_TLS_CLIENT)
        context.check_hostname = False
        context.verify_mode = ssl.CERT_NONE          # chỉ cần biết server CHẤP NHẬN cipher, không cần tin nó
        context.set_ciphers(f"{cipher_string}:@SECLEVEL=0")
        context.maximum_version = ssl.TLSVersion.TLSv1_2
        try:
            with socket.create_connection((host, port), timeout=PROBE_TIMEOUT) as sock:
                with context.wrap_socket(sock, server_hostname=host):
                    accepted.append(label)
        except (OSError, ssl.SSLError):
            continue
    return accepted
```
RC4 bị bẻ gãy bằng phân tích thống kê (dùng trong tấn công như RC4 NOMORE); 3DES dính lỗ hổng SWEET32 (birthday attack trên block 64-bit); NULL/anonymous cipher **không mã hóa hoặc không xác thực gì cả** — tệ nhất trong 3 nhóm. `@SECLEVEL=0` cần thiết vì OpenSSL hiện đại **mặc định chặn** các cipher này ở mức bảo mật cao hơn — phải tự hạ mức để "mời" server dùng cipher yếu, giống hệt lý do `_probe_legacy_tls` cần nó.

### 4. Thiếu TLS 1.3 — suy luận chứ không "dò"

Khác với TLS cũ (phải dò vì client mặc định sẽ *bỏ qua* phiên bản thấp hơn phiên bản nó hỗ trợ), TLS 1.3 không cần dò: `ssl.create_default_context()` **luôn ưu tiên phiên bản cao nhất hai bên cùng hỗ trợ**. Nếu kết nối mặc định (client hỗ trợ tới TLS 1.3) chỉ thỏa thuận được `"TLSv1.2"`, suy ra ngay server **chưa có** TLS 1.3 — không cần kết nối thêm lần nào:
```python
if tls_version == "TLSv1.2":
    findings.append({"name": "tls13_unsupported", "severity": "low", ...})
```
→ Severity `low` vì đây là **thiếu nâng cấp**, không phải lỗ hổng — TLS 1.2 cấu hình đúng vẫn an toàn.

### 5. Test cần che cả `_probe_weak_ciphers` lẫn `_probe_legacy_tls`

Vì hai hàm dò đều có thể mở kết nối mạng thật, `tests/conftest.py` có **2 fixture `autouse`** thay cả hai bằng bản giả trả về `[]`:
```python
@pytest.fixture(autouse=True)
def _no_real_weak_cipher_probe(monkeypatch):
    monkeypatch.setattr(ssl_tls, "_probe_weak_ciphers", lambda host, port: [])
```
Test nào muốn kiểm tra chính hàm dò thì **gọi hàm thật, trên một cổng đã đóng** (`socket.bind(("127.0.0.1", 0))` lấy cổng trống rồi đóng ngay) — bảo đảm không có kết nối thật nào thành công, nhưng vẫn chạy đúng code thật của hàm dò (`test_weak_cipher_probe_finds_nothing_when_the_port_is_closed`).

### 🔑 Takeaway (bổ sung)

1. **Lỗi xác minh chứng chỉ xảy ra *trong* bắt tay, trước khi đọc được nội dung chứng chỉ** — muốn phân loại lý do, phải đọc từ chính exception (`verify_code`/`verify_message`), không phải từ `getpeercert()`.
2. **Một số thứ suy luận được, không cần dò thêm** (TLS 1.3) — chỉ dò (mở thêm kết nối) khi thật sự không có cách nào biết được từ kết nối đã có.
3. **Set cipher cụ thể + hạ `@SECLEVEL`** là kỹ thuật dùng lại được cho mọi loại "dò xem server có còn chấp nhận thứ yếu X không" qua TLS.
