# Task 2.6 — API: Health Check & System Status (`GET /api/v1/health`)

> **Mục tiêu:** Cung cấp endpoint giám sát trạng thái hoạt động (Liveness/Readiness probe) của WebGuard Backend, trả về metadata môi trường, phiên bản Python, uptime hệ thống và số lượt quét đã thực hiện.

---

## 🧭 1. Health Check Endpoint là gì & Tại sao lại cực kỳ quan trọng?

Trong các hệ thống thực tế (đặc biệt khi triển khai với Docker, Kubernetes, AWS hoặc Cloud), server cần một cơ chế để **tự kiểm tra xem mình có đang sống khỏe hay không**.

- **Liveness Probe:** "Server có bị treo (freeze/deadlock) không?" Nếu gọi endpoint này mà timeout hoặc trả mã lỗi `500` -> Hệ thống quản lý container sẽ tự động restart server.
- **Readiness Probe:** "Server đã sẵn sàng nhận traffic người dùng chưa?"
- **Operational Metrics:** Cung cấp thông tin phiên bản code, phiên bản Python, thời gian uptime để đội DevOps/Dev kiểm tra nhanh sau khi deploy.

---

## 📚 2. Cấu trúc Response của `/api/v1/health`

Endpoint: `GET /api/v1/health`

### Dữ liệu mẫu trả về:
```json
{
  "status": "healthy",
  "service": "webguard-backend",
  "version": "0.1.0",
  "environment": "development",
  "demo_mode": false,
  "python_version": "3.12.10",
  "started_at": "2026-09-16T12:50:00.000000+00:00",
  "uptime_seconds": 125.4,
  "total_scans": 3
}
```

### Giải thích các trường:
1. **`status`**: `"healthy"` báo hiệu dịch vụ hoạt động bình thường.
2. **`service` & `version`**: Định danh dịch vụ và phiên bản release hiện tại.
3. **`environment`**: Môi trường chạy (`development`, `testing`, `production`).
4. **`demo_mode`**: Trạng thái bật/tắt chế độ demo an toàn.
5. **`python_version`**: Phiên bản runtime Python đang thực thi.
6. **`started_at` & `uptime_seconds`**: Thời điểm bắt đầu chạy và số giây server đã hoạt động liên tục (tính bằng `datetime.now(timezone.utc) - _started_at`).
7. **`total_scans`**: Tổng số phiên quét đang lưu trong bộ nhớ server.

## 💻 3. Chi tiết Cài Đặt (Code Walkthrough)

### 3.1. Thiết kế Module Tách Biệt (`backend/app/api/v1/health.py`)

Trước đây, endpoint health check được viết inline tạm thời trong `main.py`. Ở Task 2.6, chúng ta tách riêng thành một router chuẩn mực:

```python
from datetime import datetime, timezone
import logging
import platform
from fastapi import APIRouter, Request, status
from app.api.v1.scan import scan_jobs

router = APIRouter(tags=["Health"])

# Ghi lại thời điểm server khởi động khi module được nạp
_started_at = datetime.now(timezone.utc)

@router.get("/health", status_code=status.HTTP_200_OK)
async def health_check(request: Request) -> dict:
    settings = request.app.state.settings
    now = datetime.now(timezone.utc)
    uptime_seconds = (now - _started_at).total_seconds()

    return {
        "status": "healthy",
        "service": "webguard-backend",
        "version": settings.APP_VERSION,
        "environment": settings.ENV,
        "demo_mode": settings.DEMO_MODE,
        "python_version": platform.python_version(),
        "started_at": _started_at.isoformat(),
        "uptime_seconds": round(uptime_seconds, 1),
        "total_scans": len(scan_jobs),
    }
```

### 3.2. Lưu ý quan trọng: Dependency qua `request.app.state`
Khi chạy test suite, `TestClient` có thể tạo app với config riêng (ví dụ `ENV="testing"`). Để đảm bảo endpoint đọc đúng config của ứng dụng mà không bị cache bởi hàm `get_settings()`, ta lưu config vào `app.state.settings` trong factory `create_application()`.

## 🔑 Tóm tắt cốt lõi (Takeaway)

1. **Health Check Endpoint** là tiêu chuẩn bắt buộc cho mọi API chuyên nghiệp phục vụ việc theo dõi trạng thái hệ thống (Monitoring, Docker/K8s Liveness Probe).
2. **Uptime calculation**: Sử dụng module-level timestamp kết hợp `timezone.utc` để tính toán thời gian chạy chính xác mà không bị ảnh hưởng bởi múi giờ.
3. **Kiến trúc module hóa**: Tách riêng router `health.py` giúp `main.py` chỉ làm nhiệm vụ khởi tạo ứng dụng (Factory pattern) sạch sẽ và dễ bảo trì.
