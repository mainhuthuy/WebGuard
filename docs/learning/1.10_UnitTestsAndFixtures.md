## 📚 Lý thuyết: Tại sao cần Unit Test và Mocking trong Security Scanner?

### 1. Vấn đề khi test bằng mạng thật
- **Chậm:** mỗi request mất 1–3 giây → vài chục test mất vài phút.
- **Flaky (lúc đúng lúc sai):** mạng chập chờn hoặc server bên thứ ba down làm test fail dù code đúng.
- **Khó tái hiện ca khó:** không dễ tìm server thật luôn cấu hình sai CORS reflection hay set cookie thiếu cờ.
- **Có thể gây hại:** scanner gửi request tới site người khác mỗi lần chạy test.

### 2. Công cụ
- **`pytest.fixture`:** định nghĩa đối tượng giả (mock response, dữ liệu mẫu) **một nơi** (`conftest.py`), dùng chung cho mọi file test.
- **`unittest.mock.patch`:** chặn cuộc gọi mạng (`httpx.AsyncClient.get`) và trả response giả ngay trong RAM.
- **`monkeypatch`:** fixture của pytest để thay thuộc tính/hàm/biến môi trường *chỉ trong phạm vi một test* rồi tự khôi phục.
- **`pytest-asyncio` (`asyncio_mode = "auto"`):** cho phép viết `async def test_...` mà không cần decorator.

## 🧪 `conftest.py` làm gì?

### 1. Cô lập database (quan trọng)

```python
import os, tempfile

_TEST_DB_DIR = tempfile.mkdtemp(prefix="webguard_tests_")
os.environ["WEBGUARD_DB_URL"] = f"sqlite:///{_TEST_DB_DIR}/test.db"   # TRƯỚC khi import `app`
```

- `engine` của SQLAlchemy được tạo **ngay lúc import** `app.db.session`, nên biến môi trường phải được đặt **trước** khi import `app`.
- Nếu thiếu bước này, test tích hợp ghi thẳng vào `webguard.db` của môi trường dev → **làm bẩn lịch sử quét thật** (lỗi đã từng xảy ra ở project này).
- `TestClient(app)` dùng không có `with` thì **không chạy `lifespan`** (nơi gọi `init_db()`), nên một fixture `scope="session", autouse=True` gọi `init_db()` để tạo bảng một lần.

### 2. DNS giả cho kiểm tra SSRF

```python
@pytest.fixture(autouse=True)
def _fake_dns(monkeypatch):
    async def fake_resolve(hostname):
        return ["93.184.216.34"]          # một IP public
    monkeypatch.setattr(security, "_resolve", fake_resolve)
```

- Test không phụ thuộc mạng/DNS thật; test muốn kiểm tra "tên miền trỏ về IP nội bộ" thì tự `monkeypatch` lại `_resolve`.
- **Chỉ** giả bước phân giải của `app.core.security`, **không** patch `socket.getaddrinfo` toàn cục — vì `httpx` cũng dùng nó; patch toàn cục sẽ khiến mọi kết nối đi tới một IP ảo rồi chờ timeout (bài học: test chạy 80 giây thay vì 15 giây).

### 3. Response mẫu

`mock_insecure_headers_response`, `mock_secure_headers_response`, `mock_insecure_cookie_response`, `mock_secure_cookie_response`… — các `httpx.Response` dựng sẵn để test module không cần mạng.

## 🔑 Takeaway

1. **Mock mạng** → test nhanh, ổn định, tái hiện được mọi tình huống.
2. **`conftest.py`** là nơi đặt fixture dùng chung *và* cấu hình cô lập môi trường test.
3. **Cô lập tài nguyên có trạng thái** (database, file, biến môi trường): test không bao giờ được chạm dữ liệu thật.
4. **Patch đúng chỗ, đúng phạm vi:** patch quá rộng (toàn cục) gây tác dụng phụ khó đoán.
5. Test các **nhánh khó xảy ra** bằng cách tách code khó test thành hàm nhỏ có thể thay thế (vd: `_fetch_certificate` trong `ssl_tls.py`).
