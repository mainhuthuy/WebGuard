# Task 2.12 — Kiểm Thử Tích Hợp Toàn Diện (Integration Tests) Với FastAPI `TestClient`

> **Mục tiêu:** Xây dựng bộ Integration Tests và kịch bản End-to-End (E2E) workflow kiểm thử toàn diện mọi luồng nghiệp vụ API trong WebGuard: từ khởi tạo scan, SSE stream, xem chi tiết, xuất báo cáo HTML/JSON, theo dõi lịch sử đến cơ chế hủy và dọn dẹp dữ liệu.

---

## 📚 1. Lý thuyết nền tảng

### 1.1 Kim tự tháp kiểm thử (Testing Pyramid) trong Backend Development

```
         / \
        /   \      E2E Tests (Luồng nghiệp vụ trọn vẹn người dùng)
       /  ▲  \     ---------------------------------------------------
      /  / \  \    Integration Tests (Tích hợp Router + Service + DB)
     /  /   \  \   ---------------------------------------------------
    /  /  ▲  \  \  Unit Tests (Từng hàm, regex, Pydantic, Module đơn lẻ)
   /_____________\
```

* **Unit Tests (Sprint 1)**: Đã kiểm tra tính đúng đắn của từng module quét riêng biệt (`HeadersModule`, `CookiesModule`, `ScoringEngine`...) với mock responses.
* **Integration Tests (Sprint 2 - Task 2.12)**: Kiểm tra sự **phối hợp nhịp nhàng** giữa các tầng:
  $$\text{HTTP Request} \longrightarrow \text{FastAPI Router} \longrightarrow \text{Service Layer} \longrightarrow \text{SQLite Database}$$

---

### 1.2 Cơ chế hoạt động của FastAPI `TestClient`

FastAPI sử dụng `TestClient` kế thừa từ `starlette.testclient` và thư viện `httpx`:
* **Không cần bind port TCP thực tế**: Khi chạy test, `TestClient` không mở port mạng (như 8000), mà trực tiếp gửi đối tượng HTTP Request vào giao diện ASGI (`app`) trong bộ nhớ RAM.
* **Tốc độ thực thi cực nhanh**: Hàng chục test case hoàn thành chỉ trong vài giây.
* **Kiểm tra Response chuẩn hóa**: Dễ dàng assert mã trạng thái (`status_code`), headers (ví dụ `Content-Disposition`, `Content-Type: text/event-stream`) và dữ liệu JSON trả về (`response.json()`).

---

### 1.3 Kịch bản kiểm thử End-to-End (E2E Workflow)

Một kịch bản E2E kiểm tra chu trình hoàn chỉnh của một người dùng thực tế:

```
[1. Kiểm tra Health] ──► [2. Tạo Scan (POST /scan)] ──► [3. Nhận SSE Stream]
                                                                  │
[6. Xuất Báo Cáo]    ◄── [5. Xuất JSON]      ◄── [4. Lấy Kết Quả Chi Tiết]
       │
       ▼
[7. Kiểm tra Lịch Sử] ──► [8. Kiểm tra Thống Kê] ──► [9. Xóa Scan] ──► [10. Verify 404]
```

## 💻 2. Chi tiết triển khai code

### 2.1 File `backend/tests/integration/test_e2e_workflow.py`

Bao gồm các kịch bản kiểm thử trọng yếu:
1. **`test_full_scan_lifecycle_e2e`**: Duyệt qua trọn vẹn 11 bước từ tạo scan đến xóa scan.
2. **`test_scan_cancellation_workflow_e2e`**: Tạo scan $\rightarrow$ Hủy scan $\rightarrow$ Kiểm tra trạng thái `cancelled` $\rightarrow$ Thử hủy lại (bắt lỗi 400 Bad Request) $\rightarrow$ Xác nhận trạng thái trong danh sách lịch sử.
3. **`test_api_validation_errors_e2e`**: Kiểm thử các trường hợp dữ liệu đầu vào không hợp lệ (URL scheme sai, body rỗng, SSRF, định dạng xuất báo cáo sai, phân trang sai `page=0`, `page_size > 100`).
4. **`test_health_check_integration`**: Đảm bảo endpoint đo uptime và metrics hoạt động chính xác.

## 🔑 4. Key Takeaways

1. **Integration Test** là chốt chặn tin cậy nhất đảm bảo toàn bộ hệ thống phối hợp chính xác trước khi deploy hoặc chuyển sang Sprint làm Frontend.
2. Kiểm thử luôn phải bao gồm cả **Happy Paths** (luồng chạy thuận lợi) lẫn **Sad Paths / Edge Cases** (lỗi validation, lỗi logic, nhập sai dữ liệu).
3. Sử dụng `monkeypatch` giúp cô lập mạng bên ngoài, giữ cho test suite chạy hoàn toàn offline, độc lập và ổn định 100%.
