# Task 4.7 — DevSecOps in Pipeline (pip-audit + npm audit + Trivy)

> **Mục tiêu:** WebGuard là công cụ quét bảo mật cho người khác — nên chính nó không được mang lỗ hổng đã biết. Pipeline tự quét **thư viện phụ thuộc** và **Docker image** của chính dự án.
>
> File triển khai: `.github/workflows/security.yml` (mới) và bước quét thêm vào `.github/workflows/cd-publish-images.yml` (4.6)

---

## 📚 Lý thuyết

### DevSecOps & "shift left"
Đưa kiểm tra bảo mật vào pipeline **sớm** (lúc PR), không đợi đến lúc triển khai. Lỗ hổng phát hiện ở PR sửa bằng 1 dòng; phát hiện ở production thì thành sự cố.

### Hai nguồn rủi ro khác nhau
Code ta viết chỉ là một phần nhỏ. Phần lớn thứ chạy là code của người khác:
1. **Thư viện phụ thuộc** (FastAPI, axios, React...) → quét bằng `pip-audit`, `npm audit`.
2. **Image** gồm cả hệ điều hành nền (`python:3.12-slim`, `nginx:alpine`) và thư viện hệ thống (openssl, zlib...) mà `pip-audit` **không nhìn thấy** → quét bằng **Trivy**.

### Các công cụ
| Công cụ | Quét | Nguồn dữ liệu |
|---|---|---|
| **pip-audit** | package Python | PyPI Advisory / OSV |
| **npm audit** | package npm | GitHub Advisory DB |
| **Trivy** | OS package + thư viện ngôn ngữ trong image | NVD, bản tin của distro (Debian, Alpine...) |

### CVE và mức độ nghiêm trọng
CVE = mã định danh lỗ hổng công khai. Chia mức `LOW → MEDIUM → HIGH → CRITICAL` theo CVSS.

---

## 🛠 Thiết kế & lý do

### 1. Chỉ chặn (fail) khi **HIGH/CRITICAL và đã có bản vá**
```yaml
severity: CRITICAL,HIGH
ignore-unfixed: true
exit-code: "1"
```
Đây là quyết định quan trọng nhất. Nếu chặn mọi thứ, image Debian gần như **luôn** có vài CVE chưa ai vá → CI đỏ vĩnh viễn → mọi người ngừng nhìn vào nó. `ignore-unfixed` giữ cổng **có thể hành động được**: đỏ nghĩa là có việc cụ thể để làm (nâng phiên bản).

### 2. `pip-audit .` — chỉ runtime
Quét phụ thuộc khai báo trong `pyproject.toml`, **không** gồm nhóm `[dev]` (pytest, ruff...) vì chúng không có trong image.

### 3. `npm audit --omit=dev --audit-level=high`
Chỉ quét thứ nằm trong bundle production. Vite, ESLint, vitest chỉ chạy lúc build/dev, không chạy trước mặt người dùng; lỗi ở đó không nên chặn PR. `--audit-level=high` bỏ qua nhiễu mức thấp.

### 4. Hai nơi quét image, hai mục đích khác nhau
| Nơi | Khi nào | Vai trò |
|---|---|---|
| `security.yml` | PR, push, **hằng tuần** | Phát hiện sớm + phát hiện CVE mới |
| `cd-publish-images.yml` | Trước khi push registry | **Cổng cuối**: image lỗi không bao giờ lên GHCR |

Ở CD: build `load: true` (chỉ lưu local) → Trivy quét → mới `push`. Bước push dùng lại layer từ cache nên không build hai lần.

### 5. Chạy theo lịch (`schedule`)
```yaml
schedule:
  - cron: "0 3 * * 1"
```
Code không đổi nhưng CVE mới vẫn được công bố mỗi ngày. Không có lịch thì dự án "ngủ yên" sẽ không bao giờ biết mình đã có lỗ hổng.

### 6. `permissions: contents: read`
Job quét chỉ cần đọc code → cấp quyền tối thiểu.

## ✅ Kiểm chứng

Workflow chưa được chạy thật trên GitHub. Sau khi push, kiểm tra:
1. PR sửa `backend/**`/`frontend/**` → Checks hiện `pip-audit`, `npm-audit`, `Trivy` (×2).
2. Có thể thử chạy local cho nhanh:
   ```bash
   pip install pip-audit && cd backend && pip-audit .
   cd frontend && npm audit --omit=dev --audit-level=high
   docker build -t webguard-backend:scan backend && trivy image --severity CRITICAL,HIGH --ignore-unfixed webguard-backend:scan
   ```
3. Tab **Actions** → Security scan → *Run workflow* để chạy tay.

> ⚠️ **Dự kiến sẽ gặp:** lần chạy đầu có thể đỏ ngay vì dependency/base image có CVE đã vá. Đó là hệ thống làm đúng việc — cách xử lý là nâng phiên bản (hoặc cập nhật base image), **không** phải tắt cổng. Nếu có CVE không áp dụng được cho dự án, ghi rõ lý do trong `.trivyignore` thay vì hạ ngưỡng chung.

## 🔑 Bài học
1. **Quét cả hai tầng:** thư viện ngôn ngữ *và* OS trong image — công cụ này không thay thế công cụ kia.
2. **Cổng phải hành động được:** `ignore-unfixed` + chỉ HIGH/CRITICAL; cổng đỏ vĩnh viễn thì vô dụng.
3. **Quét trước khi publish:** ngăn artifact xấu ra khỏi nhà, chứ không chỉ phát hiện sau.
4. **Bảo mật thay đổi theo thời gian:** cần quét định kỳ, không chỉ khi code đổi.
