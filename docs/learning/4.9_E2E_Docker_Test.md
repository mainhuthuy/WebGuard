# Task 4.9 — End-to-End Docker Test (`docker compose up -d` từ máy sạch)

> **Mục tiêu (DoD Sprint 4):** Chỉ cần **một lệnh** `docker compose up -d` là toàn bộ hệ thống chạy đúng. Task này kiểm chứng điều đó bằng cách chạy thật, không dựa vào giả định.

---

## 📚 Lý thuyết: "máy sạch" nghĩa là gì và vì sao phải test

"Chạy được trên máy tôi" thường nhờ những thứ vô hình: file `.env` chưa commit, image/cache build từ trước, volume chứa dữ liệu cũ, biến môi trường trong shell. Test E2E trên trạng thái sạch loại từng thứ đó ra:

| Thứ có thể che lỗi | Cách loại bỏ trong test này |
|---|---|
| File chưa commit (`docker/.env`, file quên `git add`) | `git clone --no-hardlinks` từ repo → chỉ có file đã commit |
| Volume cũ | `docker compose down -v` trước khi chạy |
| Image cũ | Build lại bằng `up -d --build` từ bản clone |
| Dữ liệu cũ | Volume trống → DB tạo mới |

**E2E** khác unit/integration test: nó đi qua *toàn bộ ngăn xếp thật* — trình duyệt-side nginx → proxy `/api` → FastAPI → DB — chứ không mock thành phần nào.

### Về điểm 6: SSE dễ hỏng ở reverse proxy
Mặc định nginx **đệm** phản hồi (proxy buffering) → trình duyệt không nhận gì cho tới khi quét xong, thanh tiến trình đứng im rồi nhảy 100%. Đây là lỗi kinh điển, nên đã đọc luồng qua cổng 5173 chứ không chỉ gọi thẳng backend. Test này xác nhận luồng **đến được và đủ sự kiện**; việc nó đến *từng phần* hay dồn một lần cuối thì chưa đo.

## ⏱ Thời gian

Build từ bản clone sạch mất **~11.5 phút** (lớp cài dependency Python/npm chưa có cache). Từ lần sau, có cache thì `up` chỉ vài giây (đo được ~7s khi image đã có). Đây là chi phí **một lần** cho máy mới — đáng ghi vào hướng dẫn để người mới không tưởng nó bị treo.

> Lệnh `docker compose up -d` thuần (không `--build`) trên máy hoàn toàn chưa có image cũng sẽ tự build, nên vẫn là "một lệnh".

## ⚠️ Phát hiện trong lúc test (chưa sửa — ngoài phạm vi 4.9)

**`/api/v1/health` báo `total_scans` sai sau khi khởi động lại.** Sau khi tạo lại container, DB vẫn có scan nhưng health trả `total_scans: 0`. Nguyên nhân: `app/api/v1/health.py:42` dùng `len(scan_jobs)` — dict **trong bộ nhớ**, chỉ đếm scan từ lúc process khởi động; còn `services/history.py` đếm từ DB. Hai chỗ cùng tên nhưng nghĩa khác nhau. Nên hoặc đếm từ DB, hoặc đổi tên field thành "scans trong phiên hiện tại".

## ❌ Chưa kiểm tra
- **Máy thật sự sạch hoàn toàn** (chưa từng có Docker Desktop/image). Test này chạy trên máy đã có Docker và các image base (`python`, `node`, `nginx`) trong cache; phần pull base image chưa được đo.
- **Linux / macOS**: chỉ test trên Windows + Docker Desktop.
- **Chế độ dev** (`docker-compose.dev.yml`) và **demo**: đã test ở task 4.3; không lặp lại ở đây.
- **SSE có đến theo thời gian thực không**: cần đo thời điểm nhận từng sự kiện (vd `curl -N` kèm timestamp) hoặc xem thanh tiến trình trên UI.
- Giao diện trên **trình duyệt thật**: test bằng `curl`, chưa mở UI để xem bằng mắt.

## 🔑 Bài học
1. **Test từ bản clone, không phải từ thư mục đang làm việc** — chỉ vậy mới lộ file quên commit. (Chính lần thử đầu tiên bị lỗi `git clone` hardlink và lệnh tiếp theo lặng lẽ chạy trong thư mục gốc — một ví dụ nhỏ của việc "test tưởng là sạch mà không sạch".)
2. **Kiểm tra qua đúng đường người dùng đi** (qua nginx, cổng 5173), không chỉ gọi thẳng backend.
3. **Kiểm tra tính bền vững dữ liệu** bằng `down` / `up` thật, không chỉ tin vào cấu hình volume.
4. **Test E2E thường lòi ra lỗi nằm giữa các thành phần** — như bug `total_scans` ở trên, mà unit test riêng lẻ không thấy.
