# Task 2.1 — Cấu hình FastAPI: CORS, Middleware, Logging & Global Error Handling

> **Mục tiêu:** Thiết lập "khung xương sống" cho toàn bộ dịch vụ backend API: kiểm soát luồng request, đo thời gian xử lý, chuẩn hóa log và xử lý ngoại lệ tập trung chuẩn Enterprise.

---

## 🧭 Dành cho người mới: Web API hoạt động thế nào?

Hãy tưởng tượng hệ thống WebGuard giống như một **nhà hàng cao cấp**:
- **Khách hàng (Client/Frontend):** Trình duyệt web của người dùng.
- **Thực đơn (API Endpoints):** Danh sách các món/hành động khách có thể gọi (vd: `/api/v1/scan`, `/health`).
- **Phục vụ bàn (FastAPI Framework):** Nhận order từ khách, kiểm tra xem yêu cầu hợp lệ không, chuyển xuống bếp và bưng món ra cho khách.
- **Nhà bếp (Backend Core Services):** Nơi thực sự xử lý quét lỗ hổng mạng, tính điểm và tạo báo cáo.

Để nhà hàng vận hành chuyên nghiệp, ta không chỉ cần bếp giỏi, mà cần **quy trình phục vụ bài bản**: bảo vệ cửa ra vào (CORS), ghi sổ nhật ký từng order (Logging), bấm giờ phục vụ (Middleware), và xin lỗi khéo léo khi hết món (Error Handling).

## 📚 1. CORS (Cross-Origin Resource Sharing)

### Vấn đề thực tế
Theo chính sách an toàn mặc định của trình duyệt web (**Same-Origin Policy**):
- Frontend của bạn chạy ở địa chỉ: `http://localhost:5173` (React Vite)
- Backend của bạn chạy ở địa chỉ: `http://localhost:8000` (FastAPI)

Do khác cổng (port `5173` vs `8000`), trình duyệt sẽ **chặn đứng** mọi request từ Frontend gửi sang Backend vì coi đó là hành vi nguy hiểm từ nguồn lạ (Cross-Origin).

```
[React Frontend: 5173] ──(Gửi yêu cầu quét)──> [FastAPI Backend: 8000]
                                                       │
                                   ❌ TRÌNH DUYỆT CHẶN (CORS Error)
```

### Cách giải quyết
FastAPI cung cấp `CORSMiddleware`. Đây giống như việc Backend cấp "giấy thông hành":
*“Tôi cho phép các trang web xuất phát từ `localhost:5173` được quyền gọi API của tôi.”*

```python
# backend/app/main.py
app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173", "http://127.0.0.1:5173"],
    allow_credentials=True,
    allow_methods=["*"],  # Cho phép GET, POST, PUT, DELETE...
    allow_headers=["*"],  # Cho phép mọi HTTP header
)
```

## 📚 2. Middleware: "Trạm kiểm soát" lưu lượng

### Middleware là gì?
Middleware là một đoạn mã nằm ở giữa **Request** (yêu cầu đến) và **Response** (kết quả trả về). Mọi lượt khách ghé thăm đều phải đi qua trạm này trước khi vào API, và khi rời đi cũng phải qua trạm này trước khi về tay client.

```
Request từ Client ──> [ 🛡️ MIDDLEWARE: Bấm giờ + Gán Request-ID ] ──> API Endpoint (Xử lý)
                                                                            │
Response về Client <── [ 🛡️ MIDDLEWARE: Đính kèm Header + Ghi Log ] <───────┘
```

Trong file [`backend/app/core/middleware.py`](file:///d:/HuyMai/SelfLearning/Project/WebGuard/backend/app/core/middleware.py), chúng ta triển khai `RequestLoggingMiddleware` làm 3 nhiệm vụ quan trọng:

1. **Gán `X-Request-ID` (Căn cước định danh yêu cầu):**
   - Mỗi request khi gửi đến sẽ được cấp một mã ngẫu nhiên duy nhất (UUID), ví dụ: `d9c0e271-9c3f-...`.
   - Nếu xảy ra lỗi, lập trình viên chỉ cần lấy mã này tra trong log là thấy toàn bộ diễn biến của lượt request đó, không bị lẫn với hàng nghìn request khác.
2. **Đo độ trễ (`X-Process-Time`):**
   - Bấm giờ xem endpoint xử lý mất bao lâu (ví dụ `12.45ms`).
   - Đính kèm vào response trả về để client hoặc hệ thống giám sát biết API có bị chậm không.
3. **Ghi Access Log:**
   - In ra thông tin: Phương thức (POST/GET), URL truy cập, Mã phản hồi (200, 404, 500) và thời gian thực hiện.

## 📚 3. Structured Logging (Ghi log có cấu trúc)

### Tại sao không dùng lệnh `print()`?
- `print()` chỉ in chuỗi text thô ra màn hình console máy tính.
- Trong môi trường thực tế (Production), có hàng triệu dòng log mỗi ngày. Các công cụ giám sát hiện đại (ELK Stack, Grafana Loki, Datadog) cần đọc log dạng **JSON** để lọc, tìm kiếm và tạo biểu đồ cảnh báo tự động.

### Triển khai trong WebGuard
File [`backend/app/core/logging.py`](file:///d:/HuyMai/SelfLearning/Project/WebGuard/backend/app/core/logging.py):
- **Khi phát triển (Dev):** In log ra console với màu sắc trực quan, dễ đọc bằng mắt.
- **Khi chạy thật (Production):** Xuất log dưới định dạng chuẩn JSON:
  ```json
  {
    "timestamp": "2026-09-16T12:00:00Z",
    "level": "INFO",
    "message": "POST /api/v1/scan -> 201 (15.2ms)",
    "request_id": "d9c0e271-9c3f-4e08-963d-52fa619d8542",
    "client_ip": "127.0.0.1"
  }
  ```

## 📚 4. Global Error Handling (Xử lý lỗi tập trung)

### Vấn đề
Nếu không bắt lỗi cẩn thận, khi code gặp trục trặc (ví dụ cơ sở dữ liệu sập, nhập sai ID):
- Trình duyệt sẽ nhận về một trang lỗi HTML xấu xí hoặc mã lỗi `500 Internal Server Error`.
- Lộ mã nguồn (traceback) ra ngoài — **đây là rủi ro rò rỉ thông tin bảo mật (Information Disclosure)**.

### Giải pháp trong WebGuard
File [`backend/app/core/errors.py`](file:///d:/HuyMai/SelfLearning/Project/WebGuard/backend/app/core/errors.py):
Tất cả mọi lỗi xảy ra ở bất kỳ đâu đều được gom về một mối và trả về dạng JSON đồng nhất, thân thiện với Frontend:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Dữ liệu gửi lên không hợp lệ. Vui lòng kiểm tra lại.",
    "details": [
      {
        "field": "body -> url",
        "message": "URL phải bắt đầu bằng giao thức http:// hoặc https://"
      }
    ]
  }
}
```

Chúng ta phân loại và bắt 4 nhóm ngoại lệ:
| Loại lỗi | Khi nào xảy ra? | Mã HTTP |
|---|---|---|
| `WebGuardException` | Lỗi nghiệp vụ chuyên biệt của app (vd: quét URL cấm, scan_id không tìm thấy) | 400 / 404 / 429 |
| `RequestValidationError` | Người dùng nhập thiếu trường hoặc sai định dạng dữ liệu (do Pydantic bắt) | 422 |
| `StarletteHTTPException` | Lỗi HTTP chuẩn (vd: gõ sai đường dẫn API dẫn đến 404 Not Found) | 404 / 405 |
| `Exception` (Unhandled) | Lỗi bất ngờ chưa lường trước (tránh sập app và giấu chi tiết nhạy cảm khi ở Production) | 500 |

## 🔑 Tóm tắt cốt lõi (Takeaway)

1. **CORS:** Cánh cổng bảo vệ trình duyệt, cho phép React kết nối an toàn với FastAPI.
2. **Middleware:** Trạm gác tự động đo tốc độ (`X-Process-Time`) và cấp mã định danh (`X-Request-ID`) cho mọi request.
3. **Structured Logging:** Thay thế `print()` bằng JSON Log giúp dễ dàng phân tích sự cố trong hệ thống lớn.
4. **Global Error Handling:** Chuẩn hóa toàn bộ thông báo lỗi về cấu trúc JSON `{ success: false, error: {...} }`, không làm sập server và không làm lộ mã nguồn nhạy cảm.
