## 📚 Lý thuyết: Vì sao cần phân tích HTML, không chỉ headers?

Headers cho biết server *cấu hình* gì (CSP, HSTS...), nhưng không cho biết **trang thực tế có tuân thủ cấu hình tốt hay không**. Hai ví dụ:
- Một trang HTTPS khai báo CSP đầy đủ, nhưng vẫn `<script src="http://cdn.example.com/a.js">` — tải script qua HTTP thuần ngay trên trang HTTPS (gọi là **mixed content**). Trình duyệt chặn active mixed content trong nhiều trường hợp, nhưng không phải luôn luôn, và server-side scanner cần tự phát hiện việc này để cảnh báo sớm.
- Một trang nhúng `<script src="https://cdn.jsdelivr.net/npm/jquery@1.9.1/dist/jquery.min.js">` — HTTPS, CORS không vấn đề gì, nhưng **phiên bản jQuery này có lỗ hổng XSS đã công bố**. Không có header nào nói lên điều đó.

→ Cần đọc **nội dung HTML**, không chỉ metadata của response.

## 📚 Lý thuyết: Parse HTML bằng `html.parser` (thư viện chuẩn, không cài thêm gì)

Python có `html.parser.HTMLParser` trong thư viện chuẩn — một **SAX-style parser**: thay vì dựng cả cây DOM trong bộ nhớ (như `BeautifulSoup`), nó gọi callback mỗi khi gặp một thẻ, theo đúng thứ tự xuất hiện trong văn bản:

```python
from html.parser import HTMLParser

class _PageParser(HTMLParser):
    def handle_starttag(self, tag: str, attrs: list[tuple[str, str | None]]) -> None:
        # Gọi mỗi khi gặp thẻ MỞ, vd <script src="...">
        ...

    def handle_endtag(self, tag: str) -> None:
        # Gọi mỗi khi gặp thẻ ĐÓNG, vd </form>
        ...
```

**Vì sao không dùng BeautifulSoup?** Dự án đã có `httpx`, không muốn thêm dependency chỉ để parse HTML một lần cho một mục đích hẹp (tìm thẻ + thuộc tính). `HTMLParser` đủ dùng và **không cần cài package ngoài**.

**Đánh đổi:** không dựng cây DOM nghĩa là không truy vấn kiểu `soup.select("form input[type=password]")` được. Thay vào đó, project **tự gom dữ liệu cần thiết trong lúc duyệt**, dùng một biến trạng thái theo dõi "đang ở trong thẻ `<form>` nào":

```python
def __init__(self) -> None:
    super().__init__(convert_charrefs=True)
    self.forms: list[dict] = []
    self._form: dict | None = None   # form đang mở, None nếu không ở trong form nào

def handle_starttag(self, tag, attrs):
    a = {k.lower(): (v or "") for k, v in attrs}
    if tag == "form":
        self._form = {"method": a.get("method", "get").lower(), "action": a.get("action", ""), "inputs": []}
        self.forms.append(self._form)
    elif tag == "input" and self._form is not None:
        self._form["inputs"].append({"type": a.get("type", "text").lower(), "name": a.get("name", ""), "value": a.get("value", "")})

def handle_endtag(self, tag):
    if tag == "form":
        self._form = None   # đóng form -> input sau đó không thuộc form này nữa
```

> ⚠️ **HTML thật ngoài đời rất "bẩn"** (thẻ không đóng, lồng sai...). `HTMLParser` cố gắng dung thứ lỗi (giống trình duyệt), không ném exception khi gặp cú pháp lạ — quan trọng vì module này chạy trên HTML của **site bất kỳ**, không kiểm soát được chất lượng input.

## 📚 5 nhóm kiểm tra

### 1. Mixed Content — `severity: high` (active) / `low` (passive)

Trang phục vụ qua HTTPS nhưng tải tài nguyên qua HTTP thuần:
```python
def _mixed_content(self, page, base):
    active = [s for s in (script_srcs + style_hrefs + iframe_srcs) if s.lower().startswith("http://")]
    passive = [s for s in img_srcs if s.lower().startswith("http://")]
```
- **Active** (script/CSS/iframe) = `high` — kẻ tấn công trên đường truyền (Wi-Fi công cộng, ISP độc hại) có thể **thay nội dung** script đó bằng mã của mình, chạy với toàn quyền trên trang.
- **Passive** (ảnh/media) = `low` — chỉ lộ/nội dung ảnh có thể bị thay, không chạy được mã.
- Dùng `urljoin(base, src)` để quy về URL tuyệt đối trước khi kiểm tra scheme — `src="//cdn.com/a.js"` (protocol-relative) hay `src="/local.js"` (tương đối) đều phải được "giải mã" đúng dựa theo `base`.

### 2. Thiếu SRI (Subresource Integrity) — `severity: medium`

```html
<!-- Không có SRI: nếu CDN bị xâm nhập, mã độc chạy thẳng trên site này -->
<script src="https://cdn.example.com/lib.js"></script>

<!-- Có SRI: trình duyệt tự so sánh hash, sai thì KHÔNG chạy script -->
<script src="https://cdn.example.com/lib.js" integrity="sha384-..." crossorigin="anonymous"></script>
```
Chỉ kiểm tra script/CSS **bên thứ ba** (`_is_third_party`: hostname khác domain trang, và không phải subdomain của nó) — tài nguyên tự host không cần SRI vì rủi ro "CDN bị xâm nhập" không áp dụng.

### 3. Form nguy hiểm — 3 kiểu con

- **`password_form_http`** (`critical`): có `<input type="password">` nhưng trang phục vụ qua HTTP — mật khẩu gửi dạng văn bản thuần.
- **`insecure_form_action`**: trang HTTPS nhưng `<form action="http://...">` — dữ liệu submit đi qua kênh không mã hóa dù trang hiển thị là an toàn.
- **`form_without_csrf_token`** (`low`, **heuristic**): form `method="post"` không có input `type="hidden"` tên chứa `csrf`/`token`/`nonce`... Đây **chỉ là phỏng đoán** — CSRF có thể được chặn bằng cách khác (cookie `SameSite`, custom header kiểm tra qua JS) nên severity thấp và mô tả ghi rõ "kiểm tra heuristic".

### 4. Thư viện JS lỗi thời — so khớp phiên bản bằng regex trên URL

```python
VULNERABLE_LIBRARIES = [
    ("jQuery", re.compile(r"jquery[-.@/]v?(\d+\.\d+(?:\.\d+)?)", re.IGNORECASE), (3, 5, 0), "XSS (CVE-2020-11022/11023)"),
    ("AngularJS", re.compile(r"angular(?:js)?(?:\.js)?[-.@/]v?(1\.\d+(?:\.\d+)?)", re.IGNORECASE), None, "đã hết hỗ trợ..."),
    ...
]
```
`min_safe=None` (trường hợp AngularJS) nghĩa là **mọi** phiên bản bắt được đều lỗi thời — AngularJS 1.x đã ngừng hỗ trợ hoàn toàn (khác với Angular 2+, một framework khác tên gần giống). So sánh phiên bản bằng tuple `(major, minor, patch)` thay vì so sánh chuỗi (`"3.5.0" < "3.10.0"` sai nếu so chuỗi, vì `"1" < "5"` nhưng `"10"` bắt đầu bằng `"1"`):
```python
def _version_tuple(text: str) -> tuple[int, ...]:
    return tuple(int(p) for p in text.split("."))
outdated = min_safe is None or _version_tuple(version) < min_safe
```

```python
async def scan(self, url: str, **kwargs) -> list:
    async with httpx.AsyncClient(timeout=HTTP_TIMEOUT) as client:
        response = await client.get(url)
    if "html" not in response.headers.get("content-type", "").lower():
        return []   # JSON API, ảnh... -> không có gì để phân tích

    page = _PageParser()
    page.feed(response.text[:MAX_HTML_CHARS])   # giới hạn 1MB, tránh HTML khổng lồ làm chậm parser

    findings = []
    if base.lower().startswith("https://"):
        findings.extend(self._mixed_content(page, base))
    # ... các check còn lại
    return findings
```
`MAX_HTML_CHARS = 1_000_000` là một **giới hạn an toàn** (safety limit) — trang web thông thường vài trăm KB; nếu server trả về nhiều MB (lỗi, hoặc cố tình), parser vẫn chỉ xử lý 1MB đầu thay vì treo máy.

## 📚 Cập nhật: thêm kiểm tra chủ động rủi ro thấp — Username Enumeration

> Ban đầu `ContentModule` chỉ có 4 nhóm kiểm tra ở trên, toàn bộ đều **thụ động** (chỉ đọc 1 response GET có sẵn). Sau khi bàn với người dùng về việc có nên thêm các kiểm tra "kiểu tấn công" hay không, quyết định cuối: **không** thêm XSS/SQLi injection hay brute-force thật (rủi ro tấn công trái phép quá cao với một scanner nhận URL bất kỳ không xác minh chủ sở hữu), nhưng **có** thêm đúng 1 kiểm tra chủ động, rủi ro thấp: username enumeration.

### Username Enumeration là gì?

Một lỗi phổ biến: form đăng nhập trả **thông báo khác nhau** tùy theo username có tồn tại hay không:
```
Đăng nhập với "admin" + sai mật khẩu     → "Sai mật khẩu"
Đăng nhập với "khong-ton-tai" + sai mk   → "Tài khoản không tồn tại"
```
→ Kẻ tấn công dò được **danh sách tài khoản hợp lệ** chỉ bằng cách thử nhiều username, dù chưa biết mật khẩu nào — bước chuẩn bị trước khi brute-force hoặc credential stuffing có mục tiêu.

### Vì sao đây là "rủi ro thấp", không phải brute-force?

- **Đúng 2 request POST**, không lặp lại, không thử nhiều mật khẩu.
- Mật khẩu dùng để test là một chuỗi **cố định, vô nghĩa** (`PROBE_PASSWORD = "WebGuard-Probe-Pw1!"`) — xác suất trùng mật khẩu thật gần như bằng 0, nên **không có khả năng đăng nhập thành công thật sự**.
- Không nhắm vào một tài khoản cụ thể của ai — chỉ so sánh *hình dạng phản hồi*, không cố gắng chiếm quyền truy cập.

### Tìm "form đăng nhập" mà không biết trước cấu trúc site

Không có cách nào chắc chắn 100% một form là "đăng nhập" chỉ từ HTML tĩnh — dùng heuristic: form `method="post"` có **cả** một ô `password` **và** một ô `text`/`email`:
```python
@staticmethod
def _login_form(page: _PageParser) -> dict | None:
    for form in page.forms:
        if form["method"] != "post":
            continue
        username_field = next((i["name"] for i in form["inputs"] if i["type"] in ("text", "email") and i["name"]), None)
        password_field = next((i["name"] for i in form["inputs"] if i["type"] == "password" and i["name"]), None)
        if username_field and password_field:
            return {"form": form, "username_field": username_field, "password_field": password_field}
    return None
```
Chỉ xét **form đầu tiên** khớp điều kiện — nếu trang có nhiều form giống login (hiếm), chỉ form đầu được kiểm tra, giữ số request thấp.

### Chuyển tiếp các trường ẩn (hidden field) — vì sao cần

Nhiều form có token CSRF dạng `<input type="hidden" name="csrf_token" value="...">`. Nếu bỏ qua trường này khi submit, server có thể từ chối **cả hai** request vì thiếu token hợp lệ — hai phản hồi giống hệt nhau (cùng là "thiếu CSRF token"), **che mất** sự khác biệt thật sự cần tìm. Vì vậy module gửi kèm nguyên trạng mọi input ẩn đã đọc được:
```python
hidden_fields = {i["name"]: i["value"] for i in form["inputs"] if i["type"] == "hidden" and i["name"]}
payload = {**hidden_fields, username_field: username, password_field: PROBE_PASSWORD}
```
> Giới hạn còn lại: nếu token CSRF đó là **one-time** (chỉ dùng được 1 lần, cấp mới sau mỗi GET), gửi cùng một token cho cả 2 request vẫn có thể bị server từ chối lần thứ 2. Trường hợp này module không phát hiện được gì (không phải false positive, chỉ là bỏ sót) — chấp nhận được vì mục tiêu là giảm rủi ro, không phải bắt được 100% trường hợp.

### So sánh 2 phản hồi — heuristic 3 tầng

```python
@staticmethod
def _responses_reveal_enumeration(resp_a, resp_b) -> bool:
    if resp_a.status_code != resp_b.status_code:
        return True                                    # 1. Khác mã trạng thái -> gần như chắc chắn
    has_a = any(p in text_a for p in ENUMERATION_PHRASES)
    has_b = any(p in text_b for p in ENUMERATION_PHRASES)
    if has_a != has_b:
        return True                                    # 2. Một bên có cụm "no account"/"not found"..., bên kia không
    diff = abs(len(norm_a) - len(norm_b))
    return diff > 20 and diff / max(len(norm_a), len(norm_b), 1) > 0.15   # 3. Độ dài lệch > 15%
```
Tầng 3 (độ dài) **bỏ số** (`re.sub(r"\d+", "", text)`) trước khi so sánh — nhiều trang chèn timestamp/ID ngẫu nhiên vào mỗi lần render, nếu không bỏ số thì hai phản hồi *giống hệt về nội dung* vẫn bị tính là "khác nhau" chỉ vì timestamp khác.

### 🔑 Takeaway (toàn bộ Task 1.11)

1. **`html.parser.HTMLParser`** đủ dùng cho nhu cầu hẹp (tìm thẻ + thuộc tính) — không phải lúc nào cũng cần một thư viện ngoài.
2. **Phân tích nội dung bổ sung cho phân tích header** — nhiều lỗi (mixed content, thư viện cũ) chỉ hiện ra khi đọc *bên trong* trang.
3. **"Chủ động" không đồng nghĩa "nguy hiểm"** — một kiểm tra chủ động có thể được thiết kế hẹp (đúng 2 request, mật khẩu không thể đúng, không nhắm tài khoản cụ thể) để giữ rủi ro ở mức chấp nhận được.
4. **Heuristic nên nói rõ mình là heuristic** — cả trong code (tên biến, comment) lẫn trong mô tả hiển thị cho người dùng, để không ai hiểu nhầm là kết quả chắc chắn 100%.
