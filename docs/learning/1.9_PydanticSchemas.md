# Task 1.9 — `Pydantic Schemas` (Chuẩn hoá Dữ liệu & Hợp đồng API)

> **Mục tiêu:** Sử dụng Pydantic v2 để định nghĩa các Data Contracts nghiêm ngặt cho đầu vào (URL validation) và đầu ra (Findings, Score, Response) của WebGuard Scanner.

---

## 📚 Lý thuyết: Pydantic là gì và tại sao cực kỳ quan trọng?

### 1. Vấn đề khi dùng Dictionary tự do:
Nếu một hàm trả về dictionary:
```python
return {
    "url": "https://example.com",
    "findings": [...]
}
```
- Không ai biết bên trong `findings` gồm những trường gì nếu không đọc hết toàn bộ code.
- Nếu một lập trình viên gõ nhầm key `"severty"` thay vì `"severity"`, code vẫn chạy nhưng giao diện frontend sẽ bị vỡ âm thầm!
- Nếu người dùng nhập `"abcxyz"` vào ô URL, scanner sẽ chạy và gây crash hệ thống.

### 2. Pydantic giải quyết triệt để:
- **Type Safety & Data Parsing**: Tự động ép kiểu và xác thực dữ liệu tại Runtime.
- **Fail Fast (Bắt lỗi sớm)**: Nếu dữ liệu đầu vào sai, Pydantic báo lỗi `ValidationError` ngay lập tức tại cổng API trước khi gọi hàm scan tốn thời gian.
- **Tự động sinh tài liệu OpenAPI / Swagger**: Khi đưa vào FastAPI, FastAPI sẽ tự động tạo UI tài liệu API với đầy đủ schema tương tác.

## 📚 Các Schemas Đã Xây Dựng

### 1. `SeverityLevel` (Enum)
```python
from enum import Enum

class SeverityLevel(str, Enum):
    CRITICAL = "critical"
    HIGH = "high"
    MEDIUM = "medium"
    LOW = "low"
```
→ Kế thừa cả `str` và `Enum` giúp Pydantic vừa serialize thành string trong JSON, vừa đảm bảo tính an toàn (chặn các giá trị không hợp lệ như `"urgent"` hay `"warning"`).

### 2. `ScanCreateRequest` (Input Validation)

> 📌 **Đối chiếu với project:** ở Sprint 1 ta dùng `url: HttpUrl`. Sang Sprint 2, schema đầu vào được đổi thành **`ScanCreateRequest`** (tên cũ `ScanRequest` còn tồn tại như một **bí danh**: `ScanRequest = ScanCreateRequest` trong `schemas/__init__.py`). Lý do: `HttpUrl` chỉ kiểm tra *cú pháp*, còn scanner cần thêm luật nghiệp vụ **chống SSRF** (xem 2.2) và thông báo lỗi do mình kiểm soát.

```python
from pydantic import BaseModel, Field, field_validator

class ScanCreateRequest(BaseModel):
    url: str = Field(..., description="Target URL (phải có http:// hoặc https://)")
    mode: ScanMode = Field(default=ScanMode.FULL)   # quick | full

    @field_validator("url")
    @classmethod
    def validate_target_url(cls, v: str) -> str:
        ...   # kiểm tra scheme, hostname, localhost, IP không công khai
```
- `url` là `str` + `@field_validator` thay vì `HttpUrl`: giữ nguyên chuỗi người dùng nhập (không tự thêm `/`) và cho phép tự viết luật.
- `mode` là một `Enum` (`ScanMode`): giá trị lạ như `"turbo"` bị Pydantic từ chối với lỗi 422 — không cần tự `if`.
- Trường có `default` thì **không bắt buộc** gửi lên: client cũ không gửi `mode` vẫn chạy (mặc định `full`).

### 3. `Finding`, `ScoringResult` & `ScanResponse` (Output Data Contract)
```python
class Finding(BaseModel):
    module: str
    name: str
    severity: SeverityLevel
    description: str
    remediation: str
    url: str | None = None

class ScoringResult(BaseModel):
    score: int
    grade: str
    total_findings: int

class ScanResponse(BaseModel):
    scan_id: str | None = None
    url: str
    status: ScanStatus = ScanStatus.COMPLETED
    total_findings: int
    findings: list[Finding]
    scoring: ScoringResult
```
→ Đảm bảo `Scanner.scan()` trả về dữ liệu đúng 100% cấu trúc, sẵn sàng chuyển đổi thành JSON response cho frontend mà không bao giờ lo thiếu trường.

### 4. Các schema bổ sung ở Sprint 2 (`schemas/scan.py`, `schemas/history.py`)

| Schema | Vai trò |
|---|---|
| `ScanStatus` (Enum) | `pending`, `running`, `completed`, `failed`, `cancelled` |
| `ScanMode` (Enum) | `quick`, `full` |
| `ScanEventType` (Enum) | `start`, `module_start`, `module_completed`, `scoring`, `complete`, `error` |
| `ScanCreateResponse` | Trả về ngay khi `POST /scan` (`scan_id`, `target_url`, `mode`, `status`, `created_at`) |
| `ScanDetailResponse` | `GET /scan/{id}` — đủ thông tin + `findings` + `scoring` (có thể `null`) |
| `ScanStreamEvent` | Khuôn của mỗi gói SSE (`event`, `scan_id`, `progress` 0–100, `message`, `module`, `findings`, `data`) |
| `ScanCancelResponse` | Kết quả hủy phiên quét |
| `ScanHistoryItem` / `ScanHistoryResponse` / `ScanHistoryStats` | Danh sách lịch sử có phân trang và thống kê (xem 2.11) |

> 💡 Lưu ý nhỏ: `SeverityLevel` của backend **không có `info`**, trong khi giao diện (frontend) khai báo thêm `info` cho tương lai — chỉ là kiểu dự phòng, backend chưa bao giờ sinh ra mức này.
