# Task 4.8 — Setup Scripts (`setup-dev.ps1` & `setup-dev.sh`)

> **Mục tiêu:** Người mới clone repo chỉ cần **một lệnh** là có môi trường dev chạy được — không phải đọc 150 dòng `SETUP_GUIDE.md` rồi gõ tay từng bước.
>
> File triển khai: `scripts/setup-dev.ps1` (Windows) và `scripts/setup-dev.sh` (Linux / macOS / Git Bash)

---

## 📚 Lý thuyết: một script setup tốt cần gì?

| Tính chất | Nghĩa là | Vì sao quan trọng |
|---|---|---|
| **Idempotent** (chạy lại an toàn) | Chạy lần 2, 3 không phá gì | Người dùng *sẽ* chạy lại khi gặp lỗi giữa chừng |
| **Fail fast & nói rõ** | Thiếu công cụ → dừng ngay, chỉ đúng chỗ thiếu | Tốt hơn là lỗi khó hiểu sau 3 phút cài đặt |
| **Không ghi đè dữ liệu người dùng** | Không đè `.env` đã sửa | `.env` có thể chứa cấu hình riêng |
| **Có chế độ chỉ kiểm tra** | `-CheckOnly` / `--check` | Xem máy mình thiếu gì mà không đổi gì |

---

## 🛠 Script làm gì (theo thứ tự)

1. **Kiểm tra điều kiện:** Python ≥ 3.12, Node ≥ 18 (bắt buộc); Git, Docker (chỉ cảnh báo). Thiếu mục bắt buộc → in `[FAIL]` rồi thoát mã khác 0.
2. **Tạo `.env`** từ `.env.example` cho `backend/` và `frontend/` — **bỏ qua nếu đã có**.
3. **Backend:** tạo `backend/.venv` (nếu chưa có), `pip install -e ".[dev]"`.
4. **Frontend:** `npm ci` (cài đúng theo lockfile, giống CI).
5. In hướng dẫn chạy tiếp theo.

Chế độ `-Docker` / `--docker`: bỏ qua toolchain local, chạy `docker compose -f docker/docker-compose.dev.yml up -d --build` (hot-reload, không cần cài Python/Node).

## 🔍 Các quyết định / cạm bẫy đáng nhớ

### 1. PowerShell không tự dừng khi lệnh ngoài thất bại
`$ErrorActionPreference = 'Stop'` chỉ áp dụng cho cmdlet PowerShell. Với `pip`, `npm`, `docker`... lệnh thất bại **vẫn chạy tiếp** trừ khi kiểm tra `$LASTEXITCODE`. Vì vậy script có hàm `Invoke-Checked` bọc mọi lệnh ngoài và `throw` khi exit code ≠ 0. Bash không cần vì có `set -euo pipefail`.

### 2. Ngược lại: `Stop` làm "lỗi bình thường" thành lỗi chết
Lỗi thật gặp khi kiểm thử: `docker info` khi **Docker Desktop chưa bật** ghi lỗi ra stderr; với `Stop`, PowerShell biến dòng stderr đó thành *terminating error* và script chết ở bước kiểm tra, trong khi đáng lẽ chỉ là cảnh báo. Cách sửa: hạ `$ErrorActionPreference` về `Continue` **cục bộ** quanh đúng lệnh đó, đọc exit code, rồi khôi phục.

> 🔑 Cùng một cờ vừa cứu (bắt lỗi), vừa hại (lỗi dự kiến) — phải biết lệnh nào được phép thất bại.

### 3. Đường dẫn venv khác nhau giữa các hệ điều hành
Linux/macOS: `.venv/bin/python`. Windows: `.venv\Scripts\python.exe`. Bản `.sh` chạy được cả trong Git Bash trên Windows nên tự dò cả hai. Script gọi thẳng `python` của venv thay vì `activate` — không phụ thuộc shell, không cần `source`.

### 4. So sánh phiên bản
Bash: `sort -V` để so `3.12` với `3.9` đúng (so chuỗi thường sẽ sai: `"3.9" > "3.12"`). PowerShell: ép sang `[version]`.

### 5. Line ending
`.gitattributes` đã ép `*.sh` dùng **LF** và `*.ps1` dùng **CRLF**. File `.sh` mà bị CRLF thì Linux báo `bad interpreter: ^M` — đây là lý do quy tắc đó tồn tại.

## ✅ Kiểm chứng

| Kiểm tra | Kết quả |
|---|---|
| `bash -n scripts/setup-dev.sh` (cú pháp) | OK |
| Parse `setup-dev.ps1` bằng PowerShell Parser | 0 lỗi |
| `setup-dev.sh --check` / `setup-dev.ps1 -CheckOnly` | Nhận đúng Python/Node/Git, **cảnh báo** Docker chưa bật, thoát mã 0 |
| `--docker --check` khi daemon tắt | `[FAIL]`, thoát mã 1 |

**Chưa chạy:** luồng cài đặt đầy đủ (tạo venv + `pip install` + `npm ci`) — nó sẽ xoá và cài lại `node_modules` đang dùng nên chưa chạy thử trên máy này. Nên thử trên một bản clone sạch.

---

## 🔑 Bài học
1. **Idempotent + không ghi đè** là hai điều kiện tối thiểu của script setup.
2. **Kiểm tra exit code của lệnh ngoài** trong PowerShell — nhưng đừng để stderr dự kiến làm script chết.
3. **Test cả đường lỗi**, không chỉ đường chạy đúng — bug ở mục 2 chỉ lộ ra khi Docker tắt.
